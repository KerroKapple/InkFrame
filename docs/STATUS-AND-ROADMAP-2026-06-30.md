# InkFrame 全面现状报表 + 重新排期（2026-06-30）

> 给 Kerro 的一页看全：我们做到哪了、为什么感觉"什么都没做出来"、行业能借鉴什么、接下来按什么排期做。
> 数据来源：仓库内 4 份梳理文档（PROGRESS / ARCHITECTURE-SURVEY / AUDIT-REPORT / PROGRESS-VERIFICATION-2026-06-29）+ 本会话实跑 + 2026-06 联网调研（来源见文末）。

---

## 0. 一句话结论

**地基是好地基，但房子还没盖。** 过去很长时间的精力几乎全花在"后端加固 / 重构 / 审计"上——架构（DIP/ISP/UnitOfWork/InkError/迁移/限流）非常干净、931 测试全绿——可**用户真正能用的功能很薄**，而且没有排期、文档散成一堆、看不到"在做什么"。问题不在能力，在**方向和管理**：该停止给后端镀金，转去做"创作者真正要的、看得见摸得着的功能"，并按里程碑排期。

## 1. 现状仪表盘（按"用户能用多少"评估，非架构）

| 模块 | 完成度 | ✅ 能跑通的 | 🟡 半成品/缺收口 | ⬜ 没做 |
|---|---|---|---|---|

| **Provider / API 接入** | code 60% / **实用度低** | 9 款 Provider code-complete（Gemini/OpenAI/Stability + Wanx×4/Kling×2） | 列能力时实例化全部 9 个、能力约束未在提交生效、displayName 未 i18n | 模型聚合/自定义 provider、成本估算、Quota |

| **Studio / 项目库** | ~40% | 建项目 + 建首画布、项目网格、跳画布 | — | **重命名/删除/复制/归档全无**；ARCHIVE/footer 是死 stub |

| **代码质量 / 测试** | ~90% | 931 测试绿、analyze + custom_lint 干净、覆盖率 70% 闸门、E2E 主链路 | 3 个上帝类（JobQueue 791 / GenController 645 / CanvasView 779）、缺"图标尺寸/控件高度"两档令牌→大面积硬编码 | — |

**端到端**："建项目 → 开画布 → 加节点 → 配参数 → 生成 → 看结果回写" **技术上能跑通**（有 E2E 测试佐证），但这条线之外的"创作者要的功能"基本是空的。

## 2. 核心诊断：为什么"骨架完善却什么也没做出来"

1. **精力错配**：看 git 与文档，绝大部分投入在 P0/P1/P2 后端加固、事务、限流、审计、再审计（光"梳理/审计/复核"文档就 4 份、几十个 agent、几百万 token）。这些都对，但**用户一个新功能也没多**。
2. **没有"用户价值"里程碑**：所有任务都是"修正确性/拆类/补测试"，没有一条是"让创作者能多做一件事"。于是越做越稳，却越做越没存在感。
3. **管理熵增**：`docs/` 下 PROGRESS / ARCHITECTURE-SURVEY / AUDIT-REPORT / PROGRESS-VERIFICATION + 一堆 plans，互相重叠、各说各的、没有单一事实源，也没有排期表——所以"看不到做了什么"。
4. **底层债拖住上层**：偏好不持久化、Studio 只能建不能管、Provider 选择笨重——这些"最后一公里"没做，导致即便核心闭环能跑，**体感上不像一个能用的产品**。

> 结论：**不是做得少，是做错了方向 + 没排期**。下面的路线图就是来纠偏的。

## 3. AIGC 行业借鉴（2026-06 联网调研）

### 3.1 本地/桌面工具能借鉴什么
| 工具 | 范式 | 本地/云 | 给 InkFrame 的可借鉴点 |
|---|---|---|---|
| **ComfyUI** | 节点图 | 本地 GPU | 节点图把"每一步"显式化；**最先拿到新模型**。借鉴：节点可组合、子图/模板复用 |
| **InvokeAI** | 统一画布 | 本地 GPU | v6 Unified Canvas：直接在画布上涂蒙版/草图/局部重绘 + 画廊/模型管理。借鉴：**画布即编辑器**、产物画廊 |
| **Fooocus** | 表单 | 本地 GPU | 隐藏一切参数、只留 prompt。借鉴：**新手默认极简、专家可展开** |
| **Krita AI** | 画布插件 | 本地(可接 ComfyUI) | 在熟悉的画布里做 AI。借鉴：把 AI 当"图层能力"而非独立步骤 |
| **fal / OpenRouter / Atlas Cloud** | **聚合 API** | 云(BYO-key) | **一个 Key 换 model-id 就能切几十个模型**。借鉴：见 §3.3，这是 InkFrame 的最大杠杆 |

关键洞察：**节点图强但学习成本高，画布对 80% 用户更友好**。InkFrame 已是"节点画布"混合体——方向对，但要补 InvokeAI 式的"画布内编辑 + 产物画廊"。

### 3.2 模型/功能趋势 → 该优先做的功能
- **图像 API（BYO-key 可接）**：FLUX 2、Imagen 4 Ultra（最真实）、Ideogram v3（文字）、Seedream v5 Lite（$0.026/张极致性价比）、GPT-Image-2、Nano Banana 2、Z-Image Turbo（~1s）。
- **视频 API（BYO-key 可接）**：Kling 3.0（单片 6 连镜 + 多语言唇形）、Seedance 2.0（音视频联合生成 + 跨镜头保角色一致）、Veo 3.1、Runway Gen-4.5、Wan 2.6（开源免费）、Hailuo、Pika（**首尾帧 Pikaframes**）。**原生音频已成标配**（6 家中 4 家）。
- **创作者真正要的**（按价值）：① **角色一致性**（最大痛点，"每次出现都得是同一个人"）② 参考图/风格迁移 ③ **首尾帧补间** ④ 批量/变体 ⑤ **分镜 storyboard**（脚本→分镜→动画→成片）⑥ 镜头控制 ⑦ 提示词模板/预设 ⑧ 成本可见。
- **BYO-key 限制下做不了的（要诚实）**：ControlNet/精细条件控制、LoRA 微调、任意本地模型——这些是本地 GPU 工具的地盘，InkFrame 不强求。

### 3.3 差异化与定位（这是 InkFrame 的真空位）
- **真实痛点（有据）**：订阅疲劳（"AI 税 $100+/月"、"订阅时代结束"）、数据归属/隐私焦虑、平台封号/审查、跨工具切换混乱。
- **市场两端各有缺口**：纯云 SaaS（Midjourney/Runway/Krea）数据在云、订阅锁定、隐私差；纯本地 GPU（ComfyUI）门槛高、要显卡、模型更新慢。
- **InkFrame 的空位 = 三者交集**：**无 GPU 门槛（调云）+ 本地数据隐私（无云无账号）+ 多家云模型自由切换（BYO-key）+ 节点画布编排**。这个组合目前少有人同时占全。
- **定位陈述**：*"你的 AI 创作工作室——模型用你选的、Key 用你的、数据留在你机器上。"*
- **变现路径（开源本地优先现实选项）**：捐赠/赞助、Pro 桌面增强（高级节点/批量/导出）、模板与工作流市场、团队版、可选托管同步——**绝不把"数据上云"作为变现前提**（那会毁掉护城河）。

## 4. 重新规划：路线图 + 排期（按"最快让用户用起来"排序）

## 5. 管理改进（治"看不到做了什么"）

1. **单一事实源**：把散落的 PROGRESS/SURVEY/AUDIT/VERIFICATION + plans **归档**，建**一块活看板**（`docs/BOARD.md` 或 GitHub Projects），字段固定：`模块 | 功能 | 状态(未开始/进行中/完成) | 优先级 | 里程碑(M1/M2/M3) | 负责人 | 备注`。
2. **每条任务都问一句**："这让用户能多做什么？"——答不上来的，降优先级。
3. **每个里程碑一条可演示主线**：M1 结束能录一段"开 app→建项目→生成→看到进度→结果回写、重启还在"的演示。看得见，才不焦虑。
4. 后端加固/重构改为**"挡路才做"**，不再主动镀金。

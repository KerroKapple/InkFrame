# Handoff: InkFrame 桌面端 UI 重构（画布 / 序列 / Studio / 画廊 / 设置）

## Overview

为 `KerroKapple/InkFrame`（Flutter 桌面端 AI 影视工作台，v0.1.0-alpha.9）设计的一套完整界面方案，覆盖十个界面中的全部主要视图。核心改动有三项：

1. **导航结构**：把 `_UnlockedShell` 的四态互斥整屏切换，改为持久的工作区标签（Studio / 画布 / 序列 / 画廊），切换不销毁彼此状态；设置从整屏替换改为浮层。
2. **新增「序列」视图**：把原先拆成两个模态的故事板（脚本导入 / 序列预览）合并为一个常驻视图，并承载粗剪与「一次性交付到剪辑软件」的能力。
3. **视觉语言**：Adobe（Photoshop / Premiere）式的桌面工具审美——中性灰面板分层、单一琥珀强调色、细分隔线代替卡片框、高密度但留白克制。

配套的信息架构分析（路由判据、十界面清单、主线八步、七处断点 B1–B7、三个导航方案对比）在 `InkFrame-IA.dc.html`，建议先读它再读界面稿。

## About the Design Files

本包内的 `.dc.html` 文件是**用 HTML 制作的设计参考**——用来表达预期的外观、布局尺寸与交互，**不是可直接复制进产品的代码**。

目标是在 InkFrame 现有的 **Flutter 桌面端环境**中重建这些设计，沿用仓库已有的模式与基础设施：

- 主题与色值走 `lib/theme/tokens.dart` 的 `InkColors` 与 `lib/theme/typography.dart`，不要硬编码本文档里的十六进制值——下方「Design Tokens」一节给出的是**设计值与现有 token 的映射关系**，落地时引用 token。
- 状态管理沿用现有的 Riverpod provider（`currentCanvasId` / `currentGalleryProject` / `currentScreen` / `jobsRegistry` 等）。
- 数据层沿用现有的 Drift/Postgres 迁移池与 `lib/features/*/data` 下的 repository。
- 组件放在对应 feature 目录的 `widgets/` 下，遵循现有的文件命名与分层。

HTML 里的所有交互（hover、选中态、标签切换）都是静态呈现的，需要在 Flutter 侧用真实状态实现。

## Fidelity

**High-fidelity（高保真）**。所有界面按 1600×1000 逻辑像素绘制，颜色、字号、行高、间距、分隔线、圆角均为最终值，可直接按标注实现。唯一例外是缩略图与预览画面——设计稿里用渐变色块占位，实现时替换为真实产物缩略图。

窗口最小尺寸建议 1280×800；下方各界面的「响应行为」一节说明了收窄时的取舍。

### 1b. 风格泳道（`InkFrame Lanes.dc.html`）

对应 `lib/features/canvas/models/style_lane.dart` 与 `widgets/lane_*.dart`。

**语义（重要）**：泳道是**风格容器**，不是场景分组。每条道带一个 `stylePrompt`，道内节点（通过 `lane_id`）在生成时继承该提示词。底色由 `lane_tint.dart` 的五组中英词表从提示词推断，可手动覆盖；`tintColor` 为空且推断不中时不绘底色。

**现有模型**：`label` / `stylePrompt` / `sortOrder` / `tintColor` / `size`（默认 400，下限 `kMinLaneSize` = 80）。方向是画布级字段 `lane_direction`（horizontal / vertical），非单道属性。

**几何**：横向时带沿 Y 堆叠、跨满宽；竖向时带沿 X 堆叠、跨满高（`laneRects`）。分界线为 1px，首条不画起始线。

**设计稿的六项改动**：

1. **标题栏补 stylePrompt**（新增）。现有 `LaneTitleBar` 只显示 label。改为两行：名称（12px/500 `#E8E8E8`）+ 提示词摘要（10px `#8A8A8A`，单行省略）。栏体 `rgba(38,38,38,0.82)`、高 26px、圆角 3px，左侧 8×8 色点取 tint，右侧依次为节点数（等宽 10px）与折叠 / 编辑 / 删除三个 18×18 图标键。
2. **道首 3px 饱和色轨**（新增）。0.10 alpha 的 tint 在 `#1A1A1A` 上几乎不可见。保留该弱底色（不干扰缩略图），另在道首（横向为左缘，竖向为上缘）加一条 3px 满饱和 tint 色轨。
3. **节点标注继承来源**（新增）。节点底部一行：6px 方色点 + 「继承 黄昏 · 山径」（10px `#8A8A8A`）。跨道拖动会改写 `lane_id` 从而改变风格，这是一次需要可见反馈的语义变更。
4. **折叠态收成 36px 轨**（调整）。现状折叠仅不绘底色填充，不省空间；默认 400px 厚度下三四条道就撑满视口。改为整条收成 36px，仅保留标题栏（名称 + 节点数 + 展开箭头），底色不绘、分界线保留。
5. **标题栏宽度脱离道厚**（修复 BOARD P2-3）。现状竖向末道小于约 200px 时标题栏按钮不可命中，因为栏宽等于道宽。改为固定 268px（横向）/ `min(道宽 - 24, 240)`（竖向）。
6. **色板收敛到单一数据源**（修复）。`lane_edit_dialog.dart` 的 `_kLaneSwatches` 复刻了 `lane_tint.dart` 的五个色值，注释自述「与 `_kTintGroups` 顺序一致，但在 UI 层独立声明」。改为直接读词表常量。

**泳道编辑对话框**：现状（`lane_edit_dialog.dart`，宽 360）只有四项——名称、风格描述（多行 `minLines: 3`）、底色（「自动」chip + 五个预设色块，`_kLaneSwatches`）、实时预览框（`effectiveLaneTint` 算出的 0.15 alpha 色块）。**没有预设 chip**（`base_style_presets.dart` 属于画布级的 `base_style_editor_dialog.dart`，与泳道无关），**也没有厚度滑块**（`size` 只能拖分界线改）。

设计稿按这四项还原，唯一改动是把「自动」项下方补一行推断结果说明（「当前命中 neon / rain → #4A78C8」），让用户知道自动挡到底选了什么。`tintColor == null` 即「自动」，是默认值。

**泳道工具栏**：画布右下角，两个键——新增泳道、方向切换（图标随当前方向变，并显示「横向 / 竖向」文字标签；现状仅图标）。

**交互**：拖拽分界线改厚度（下限 80，拖拽时显示 3px 琥珀高亮线与数值提示）；拖动标题栏重排（`reorderedLaneIds`，注意 `reorderLanes` 当前非事务，属 P1-6）；双击标题栏折叠；节点拖入某道即写 `lane_id`（`laneIdAtPoint`）；删除道时 `lane_id` 置空而非删节点，需在确认框写明。

### 8. 批量结果与角色（`InkFrame Batch & Characters.dc.html`）

#### 批量结果

对应 `lib/features/canvas/models/batch_result.dart` 与 `widgets/batch_results_grid.dart`。一次 `batch_size > 1` 的生成在 `batch_results` 表落多行，每行一个 slot；从中选一张「转正」为节点产物。

**现状**：挂在 ImageResultInspector 内，`GridView.count(crossAxisCount: 2)`，每格 `aspectRatio: 1`。`promoted` 仅体现为一圈 accent 边框。失败 slot 用 Tooltip 承载本地化文案，底部叠一行 danger 摘要。

**五项改动**：
1. **slot 改 16:9**。模型存了 `width` / `height`，应按真实比例渲染；方形格把 16:9 画面裁掉两侧，恰好是判断构图的部分。
2. **露出 `seed`**。模型已存却从不显示。批量四张的差异常常只有种子，看不到就无法复现满意的那张。每格下方标出，并提供「以该种子重跑」（⎘）。
3. **转正动作显式化**。现状没有任何按钮，用户不知道怎么改选。每格给显式动作：转正 / 当前 / 重跑 / 取消。生成中的 slot 其 ⎘ 置灰（还没有 seed）。
4. **对比浮层**。300px 栏内 2 列格宽不足 140px，判断不了细节。加足尺并排浮层：←→ 切换、↵ 转正、Esc 关闭；顶部可切「并排 / 叠加对比」。
5. **失败 slot 同时给出 `errorCode` 原串**（如 `content_filtered`），不止本地化文案，便于排障。

四种 slot 状态都要设计：success、success + promoted、error、generating。

#### 角色

对应 `models/character.dart` 与 `widgets/characters_section.dart`。

**现状（重要，与直觉不符）**：角色**不是**一个独立的库面板，而是 config 节点检查器内的一个区块 `CharactersSection`（image / video inspector 共享）。它只做两件事：
- 用 `CharacterChip` 的 Wrap 列出项目级角色，点击切换挂载（写 `type_config.character_ids`）。chip 为 20×20 缩略图 + 勾 + 名称，选中态为 accent 填充；缩略图只取 `referenceImagePaths.first`。
- 两个 TextButton：「存为角色」（从本节点第一条 reference 入边的源节点取图）与「从文件导入」。

创建角色的唯一对话框是 `InspectorNameDialog` —— **单个名称字段**，配一张图（`createFromImage`）。

因此模型里的 `description` 与多张 `referenceImagePaths` **没有任何 UI 入口**：不能添加第二张参考图、不能编辑描述、不能重排、不能改名或删除。provider 不支持参考图时（`maxRefImages <= 0`，image inspector 另需 `imageToImage` 模式）整区给一行 warning 提示。

**要补建的部分**。检查器里的挂载区保留原样（那是「用」的地方），新增两处：

1. **角色库**（画布左栏「角色」页，与画布树平级）。角色是项目级的，跨画布复用，所以入口不该藏在某个节点的检查器里。列表每行 36×36 首图缩略 + 名称 + 「4 张参考图 · 6 处引用」+ ⋯ 菜单（编辑 / 改名 / 删除）。底部虚线「新建角色」。检查器角色区加一个「管理」链接指向此处。
2. **角色编辑框**（宽 520）。名称、描述、参考图（96px 方格，显式序号 + 备注 + 删除，可拖动重排，末位为添加格）、被引用节点列表。底部提示影响范围。

**数据层现状（已读 `characters_controller.dart` 与 `character_asset_service.dart`）——比预期完整**：

| 能力 | 控制器 | UI 入口 |
|---|---|---|
| `createFromImage` | ✅ 有（含失败补偿，不留 ghost 记录/孤儿文件） | ✅ 有 |
| `rename` | ✅ 有（乐观更新 + InkError 回滚） | ❌ **无** |
| `delete` | ✅ 有（softDelete，刻意保留参考图资产以便 restore） | ❌ **无** |
| 改描述 | ❌ 无，但 `repo.update` 接受任意列 map | ❌ 无 |
| 加/删/重排参考图 | ❌ 无，但 `importImage` 的 `fileBaseName` 自由、`assets.delete` 已有 | ❌ 无 |

所以 rename 与 delete 是**已实现但够不到**——角色库的 ⋯ 菜单直接接上即可，零数据层改动。其余四项是控制器上的薄方法（`setDescription` / `addReferenceImage` / `removeReferenceImage` / `reorderReferenceImages`），全部可由现有原语组合，**不需要改仓储或迁移**。多图落盘沿用 `{id}-{n}` 命名（现固定传 `{id}-0`）。

注意 `delete` 走软删且不清资产，是为了 restore 后参考图不指向已删文件（代码注释标为「评审 F2」）——角色库的删除确认文案应说明这是可恢复的。

设计稿三栏：左「现状」、中「新增 · 角色库」、右「新增 · 编辑框」。

- ⌘K 在所有界面可用；⌘↵ 从结果直接跳到画布并定位选中该节点。

### 画布

- 节点选中：图区描边转琥珀，输出端口转琥珀，检查器与底部输入条同步切换到该节点。
- 连线拖拽：从输出端口拖到输入端口。多入边节点（如图转视频）需要在落点选择角色（起始帧 / 结束帧 / 参考帧），能力位不支持的角色应禁用。
- 提示词条：⌘↵ 提交生成。未选中节点时建议降级为「新建节点」入口（输入即在画布中央创建 image 节点）——此为建议项，未在设计稿中呈现。
- 生成中的节点状态文字转琥珀并显示百分比，与渲染队列同源（`jobsRegistry`）。

### 序列

- 拖动片段改变顺序 → 写回 narrative 边。
- 拖动片段两端裁切 → 写回镜头节点的入出点，并在片段两端显示 4px 琥珀标记。
- 双击片段 → 跳到画布并定位对应节点。
- M 键在播放头位置打标记；标记可拖动。
- 交付前检查随设置变化实时重算。
- 目标软件切换时，「工程文件 · 格式」一行随之改变。

### 画廊

- 单击选中，⌘/Shift 多选，空格快速预览，双击放大，↑↓ 切换。
- 悬停视频项自动播放（可在工具行关闭）。
- 「发送到画布」把选中产物作为新节点插入当前画布；「存为角色」写入角色库。

### 状态

需要的状态大多已存在于现有 provider。新增的主要有：工作区标签的当前值（替代互斥的 `currentScreen`）、序列视图的播放头位置与选中片段、交付设置（应按项目持久化）、画廊的筛选与选择集、命令面板的查询与结果。

### 静态复刻验收（B 路径）

每一屏先在 Flutter 里做**不接数据**的静态复刻，与稿并排比到只剩字形差异，再接 provider。工具链：

```bash
# 1. 复刻页自截图（1600×1000 逻辑像素，与显示器 DPI 无关）
flutter build windows --debug -t lib/replica_main.dart \
  --dart-define=INKFRAME_REPLICA_OUT=D:/tmp/flutter.png && build/windows/x64/runner/Debug/inkframe.exe
# 2. 稿的基准图：headless Chromium 开 2000×1250 视口渲染 standalone，裁左上 1600×1000
chrome --headless=new --disable-gpu --hide-scrollbars --force-device-scale-factor=1 \
  --window-size=2000,1250 --virtual-time-budget=15000 --screenshot=ref_raw.png "http://127.0.0.1:8765/InkFrame%20Workspace%20v2.html"
# 3. 像素比对（容差 24/255，输出差异图 + 按 20px 行带的差异分布）
powershell -File scripts/replica_diff.ps1 -A ref.png -B flutter.png -Out diff.png
# 4. Screens 稿是多屏纵排：用 1700×2400 视口整页截，再按屏的左上角裁（画廊屏在 (48,1168)）
powershell -File scripts/replica_crop.ps1 -In ref_tall.png -Out ref.png -X 48 -Y 1168
# 5. 复刻哪一屏：--dart-define=INKFRAME_REPLICA_SCREEN=gallery（默认 workspace）
```

`replica/` 存每屏的三张图：`*_reference_*.png`（稿）/ `*_flutter_*.png`（复刻）/ `*_diff.png`（红 = 差异像素）。

## 落地建议顺序

1. **工作区外壳**：改造 `_UnlockedShell`，把互斥路由换成持久标签 + 状态保留。这是其余改动的前提，也解决断点 B1/B2/B6。
2. **画布节点与连线重绘**：视觉改动量大但风险低，不涉及数据层。
3. **检查器术语与分组调整**：纯文案与布局，可与第 2 步并行。
4. **提示词输入条**：从检查器迁出，注意与画布视口的层级关系。
5. **序列视图**：工作量最大。建议先做只读的链序展示与监视器，再加裁切与标记，最后接交付导出。
6. **交付导出**：按 PRD 的优先级，EDL 与剪映草稿为 P1，FCPXML 为 P2——设计稿默认推 FCPXML 是基于 Resolve 兼容性考虑，**若要严格遵循 PRD 排期，应把默认目标改为 EDL**，这一点需要产品决策。
7. **画廊、设置浮层、命令面板搜索**：相对独立，可穿插进行。

**接线后再截一张（B 路径第二步）**：真实 app 加两个编译期开关（`lib/features/workspace/dev/dev_capture.dart`）——
`--dart-define=INKFRAME_SEED_FIXTURE=true` 在全新库里播种稿上那一屏；`--dart-define=INKFRAME_CAPTURE_OUT=…`
把 app 固定在 1600×1000 逻辑像素自截图后走正常关窗退出。把 `LOCALAPPDATA` 指到临时目录（先放一份
`onboarding_completed: true` 的 preferences.json）即可在干净库上复现。差异明显上升 = 数据长度撑破布局的信号，回设计侧调稿。

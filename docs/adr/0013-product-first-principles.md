# ADR-0013: InkFrame 产品第一性原理——节点为原子、交互为护城河、信任为第一特性

- **Status**: accepted
- **Date**: 2026-07-08
- **Deciders**: 仓库维护者（单人项目）
- **Related**: ADR-0007（节点 type×role + JSONB config，原子单位）· ADR-0009（Provider 能力声明 + 接口隔离，Provider 商品化）· ADR-0011（面向插件的扩展点，交互恒久）· `docs/MASTERPLAN.md`（本 ADR 是其上位约束与验收标尺）

> **这是一份上位 ADR。** 它不决定某个技术实现，而是约束后续所有架构决策与路线图卡片：任何卡在进入前应先过本文的原则尺。目的：**防执行漂移**——阻止 InkFrame 在日常开发中不知不觉退化成"Provider 的 UI"。

---

## Context

现在大量 AI 产品最终都收敛成三种没有灵魂的形态:ChatGPT+API、ComfyUI Launcher、Midjourney Client。一旦所依赖的 Provider（ComfyUI 倒了 / FLUX 换了 / Kling 没了 / Gemini 改版）消失,产品**什么都不剩**。

判据只有一个问题:**如果所有 Provider 明天全变,InkFrame 还剩什么?**
- 若答案是"没有"→ 它只是 Provider 的 UI。
- 若答案是"我的创作体验"→ 它才是一个产品。

**关键事实:InkFrame 的架构已经押了后者这个注。** 它选了节点画布而非聊天框（ADR-0007）,把 Provider 做成 registry 单一接入 + const 能力声明 + 接口隔离（ADR-0009/0011）——即 Provider 本就被设计成**可插拔、可抛弃**;沉淀在画布与边上的东西才是产品。因此真正的风险不是架构错,而是**执行漂移**:每天把劲儿使在"再接一个模型"上,而非画布本身。本 ADR 把这道护栏焊死。

底层信念:**优秀的 AI 产品最终靠工作流与体验留住用户,不靠模型。** 用户今天能换模型、明天能换服务商;但一旦习惯了你的创作方式、媒体管理与交互细节,就不愿离开。Provider 半年一换,交互十年不变。

## Decision

确立以下**产品第一性原理**。每条 = 一句规则 + 它对决策的约束。

### P1 — 节点是原子单位;一切表面皆 lens
媒体浏览、创作树、时间线、历史、画廊——**全都必须是同一张节点图的视图（lens），而非并列的功能面板**。节点 = type×role×config,边 = 关系（ADR-0007）。
- **拒绝**:任何需要自己的真相源、而非节点图投影的新"面板"。若一个表面无法表达为节点图的 lens,先质疑它是否违反本原则。
- **意义**:守住 → 永不变成"又加了个 XX 面板";守不住 → 三年后就是第二个臃肿的 ComfyUI。

### P2 — Provider 可弃,交互恒久;但 Provider 的失败体验属于交互
不以"再接一个模型"为默认进展。Provider 数量增长是**低杠杆**。
- **但**:生成失败 / 超时 / 限流 / 取消 / 批量半途炸——这些"怎么发生"**本身就是产品**,是穿着 Provider 外衣的交互问题(JobQueue 状态机、取消链、错误态 GAP-8/LB-05/06)。
- **验收尺**:每个接 Provider 的 PR 必须回答"它让创作体验多了什么",而不只是"多了一个模型"。

### P3 — 创作是连续的,不是一次次 API 调用
工作区（Studio+Canvas）常驻,用户永远"在创作中",而非"发起→结束→重来"。偏好 / 画布 / 窗口状态 / 历史必须持久。
- **拒绝**:任何"生成完就没了、下次从零开始"的流程。

### P4 — 媒体是一等公民（Lightroom 级）
媒体浏览体验本身就是产品力。悬停自动播、双击放大、空格暂停、方向键上/下一张——媒体不该"下载→外部播放器→回来"。
- **依赖**:XM-1（视频元数据,多 epic 阻塞点）、GA-1/GA-2（缩略图/点击播放）。
- **验收尺**:看一段生成视频要几步?目标 = 0 步跳出应用。

### P5 — 创作树:血缘即结构,但必须有"当前线"
用已有的 `generation_source` 血缘边把结果组织成树/DAG,而非扁平 History（AI 创作本质一直在"分叉")。
- **但**:纯分叉的树在规模上必然变成意大利面。DAG 底座之上必须叠一层**有主见的"当前线"**——"你在这里,这是你正在打磨的那条",其余分支默认折叠(如 Git:是 DAG,但你永远在某个分支上)。
- **拒绝**:无主线的纯分叉无限画布。

### P6 — 信任是第一产品特性
"永远不丢你的创作树"是一个一天泡 8 小时的工具的地基。数据安全、备份、导出导入、无限撤销**是产品特性,不是上线前的杂活**。
- **范围**:D-4（已拍 ADR-0012）、LB-07（SCRAM）、LB-10（备份）、LB-11/12（导出导入）、PL-4b（无限撤销）。
- **意义**:这解决了"产品哲学 vs 上线脊柱"的假矛盾——**脊柱就是哲学的地基,只是它不上镜**。一个崩溃就丢整棵树的漂亮 UX,比没有树更糟。

### P7 — 每个动作的验收线
重度创作者一天在 InkFrame 待 8 小时。**每张卡的验收都过这把尺:每个动作能不能少一次点击、少一次等待、少一次思考,以及少一次"我的东西还在吗"的担心。**
- 拖拽 / 多选 / 收藏 / 批量 / 无限撤销 / 无限历史 / 标签 / 搜索 / 自动保存 / 全键盘 / Command Palette（D-8）/ 快速切模型 / Workspace——没有一个是模型,但每天都被用。

**定位语（据此):** *A workspace where every AI creation stays connected.* —— 价值不在"生成",在"组织创作"。

## Consequences

**对路线图的重估(不删脊柱,是重排优先与重估性质):**
- **抬升为"身份特性"**（非"打磨"）:XM-1、GA-1/GA-2（P4 媒体一等公民）、创作树呈现（P5）、undo/redo（PL-4b）、⌘K 做真（D-8）。
- **重估性质**:LB/PKG 脊柱不再是"要赶完的债",而是 P6 信任的地基,保留但正名。
- **拒绝清单**:纯为广度接 Provider(P2);为 ComfyUI 兼容而引入其节点复杂度(见备选 C);无当前线的分叉画布(P5);带独立真相源的新面板(P1)。

**审查/验收标尺(每个 PR/卡过一遍):** P1(是不是 lens?)· P2(是不是只加广度?)· P7(4 个"少一次"过了几个?)。

**好的:** 有了防漂移护栏与统一验收尺,五年后 InkFrame 仍是"组织创作"的工作台,而非过期的 Provider 拼盘。
**欠的债:** 原则不自动执行——需要在评审中真的拿出来对照,否则退化成装饰性宣言。

## Alternatives Considered

### A. 成为 ComfyUI Launcher / Provider UI / Chat+API
- 否决:没有灵魂,Provider 一换即空。与架构已押的注(节点画布 + 可弃 Provider)相悖。

### B. 以模型质量为护城河
- 否决:生成质量是模型层能力,半年一换,锚不住用户。永不锚定生成质量(与 MASTERPLAN §1 定位一致)。

### C. 照搬 ComfyUI 的节点粒度
- 否决:Workflow 已是 AI 创作事实标准,**吸收其能力**(把 ComfyUI 当最大的 Workflow 数据来源去研究用户真实创作),但**不吸收其复杂度**。用户看到"图片生成",背后 20+ 节点自动完成。

### D. 纯分叉无限画布(无"当前线")
- 否决:规模化即意大利面(P5),把杀手锏做成负担。

## Revisit Triggers

- 当某个表面确实无法表达为节点图的 lens(P1 出现真实反例)时,重审"节点为原子"假设。
- 当"连续创作 / 创作树"的存储与渲染代价(节点/边规模)撞上性能墙时。
- 引入多人协作 / 同步(远期),单机连续创作的耐久与冲突模型变化时。

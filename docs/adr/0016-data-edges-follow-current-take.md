# ADR-0016: 数据边在生成时解析成上游的当前 take，不跟着 take 改写连线

- **Status**: accepted
- **Date**: 2026-11-21
- **Deciders**: Kerro
- **Related**: PRD [canvas-inputs](../prd/canvas-inputs.md)；工程审计 2026-11-20 G1 / G2 / TOPO-2；ADR-0007（type_config JSONB）；ADR-0012（前向迁移）

---

## Context

- 一个配置节点可以生成出好几个 take，「当前 take」= 固定的 ?? 最新的（`currentResultFor`）。下游节点要用的是上游「当前那张」。
- 第二批计划里的 TC-Q1 原本建议方案 A：每次出新 take 或「设为当前」时，后台把下游连线从旧 take 挪到新 take。派工单为此写了 16 条规则，涉及任务成功回调里写边、两个任务并发完成谁赢、自引用特判、画布没打开也要写库，「删掉当前 take 之后线去哪」还没有答案。
- 现在的代码里已经有一个真实缺陷：从图像**配置**节点连出的首帧 / 参考线，生成时只读源节点自己的 `image_url`。配置节点没有这个值，于是这条线被静默跳过，图生视频退化成文生视频，照样收费（审计 TOPO-2，`generation_controller.dart:707-709`）。
- 节点图类工具的通行做法：线接在上游的输出口上，执行时才解析成当前版本，例如 Flora 下游用 active 那一版，Runway 可以把旧输出换回当前。

## Decision

**决定：** 数据边只存「上游节点 + 输入口」。上游是配置节点就表示跟随它的当前 take，上游是产物节点就表示钉住那一个 take。点「生成」时由同一个解析函数（`InputResolver`）把每条线解析成具体的一张图，解析不出就阻断，不许静默降级。每次生成把实际用的 take 和路径记进产物的 `gen_inputs`。

**理由：**

1. 「当前 take」是派生事实。把它复制进持久化的连线，再派后台任务维护两边一致，每一条维护规则都是将来的竞态和撤销缺陷来源。只在用的时候算一次，就没有一致性要维护。
2. 修 TOPO-2 本来就需要「配置节点 → 当前 take」这一步解析。B′ 让这一处同时承担两件事，不用另造挪线机制。
3. 撤销变简单：「设为当前」只改一个指针（#324 的 `SetCurrentTakeCommand` 已经是这么做的），不用带上被挪动的连线。

## Consequences

**好的：**
- 不改 schema，不需要迁移。
- TC 派工单里的十几条挪线规则全部不用做。
- 「看着连上了、生成时被丢掉」从此只有一个判据，测试可以钉住它。

**坏的 / 欠的债：**
- 画布上的线画在两张卡之间，看不出用的是哪个 take，要靠检查器输入行的缩略图补上（PRD 第 4 节）。
- 产物节点不是不可变的（批量「转正」会改写 `image_url`），所以快照必须连路径一起记，只记 id 不够。
- 「钉住」和「跟随」的区别只取决于上游是产物还是配置。界面上要讲清楚，否则用户会以为连在产物上也会跟着变。

## Alternatives Considered

- **A：任务成功后改写连线**（原 TC-Q1 建议）。已否决，理由见上；`tc-take-edge-follow.md` 派工单作废。
- **B：连线存一个「跟随 / 钉住」标志，加一列**。B′ 已经能用「上游是配置还是产物」表达同样的意思，没必要加列，也不用写迁移。

## 0. 一句话结论

仓库**工程质量相当高**：DI/错误模型/freezed/迁移原子性/SQL 参数化/密钥隔离/并发裁决等核心机制**经得起严格审**。最严重的问题**不在业务代码，而在质量闸门本身**——CI 与本地 pre-commit 里那套用来强制铁律的 hook **全部空转**，外加一个 hook 有语法错误彻底死掉。结果是：团队以为被强制的铁律(零硬编码样式/字符串、DI、Disposable、i18n parity)**实际只在恰好有 flutter 测试覆盖的地方被强制**——这正好解释了为什么散落着一批硬编码样式/字符串违例没人拦。

### 2.2 接缝问题

- **CI 闸门空转 ↔ 铁律不可强制**(元接缝)：这是把上面所有 P2 样式/字符串/DI 债务"放行"的总闸门。**优先修复点**。
- **job_queue 启动恢复 ↔ S6 purgeExpired**(S7↔S6)：`job_queue_service.dart` 启动把孤儿 job 跃迁 `cancelled` 时未写 `completed_at`(约 103-110 行)，而 `postgres_job_repository.dart:165-166` 的 `purgeExpired` 谓词 `completed_at < now()-interval` 对 NULL 恒假——这些行只能靠 `purgePerCanvasCap` 按数量上限兜底，时间保留策略对它们失效。
- **下载落盘 ↔ DB 回写 ↔ 失败清理**(S7 内部)：先写文件再 `patchTypeConfig`，DB 失败抛 `LocalIOError` 但不被本方法的 catch 覆盖 → 文件成孤儿(已确证，P3)。
- **secure storage ↔ provider key**(✅ 干净)：跨 S1/S4/S5/S7 核实——API key **全程只经 `SecureStorageService`**，从不进日志/错误消息/URL query/剪贴板。这是一处**经得起审**的接缝，特此记录。

# S6 — Storage / embedded PostgreSQL

**CONCLUSION: 发现 3 条（含 1 条信息项）；核心存储机制经得起审**

## Findings

### S6-1 | P3 | [SQL-injection-hardening] | `lib/storage/base_repository.dart:83,90`（同形于 postgres_edge_repository:100-107、postgres_job_repository:110-119/141-148、postgres_batch_result_repository:86-93） | `[已确证]`
`buildUpdate` 及各 repo 动态 update/transitionStatus 把 patch/extra 的**键名**直接插值进 SQL(`setParts.add('$key = @$param')`)，只有值走 `@param`。值侧 100% 参数化无注入；键侧是列名插值。追踪所有调用方(job_queue_service 的 extra、canvas 控制器、softDeletePatch/restorePatch)——键全是源码硬编码常量，**当前不可达不可信输入**。缺列名白名单护栏：若未来有人把用户字段名当 patch key 透传，会变注入面。
- **证据**：`final sql = 'UPDATE $table SET ${setParts.join(', ')} $where';`(:90)，键来自 `patch.forEach` 无字符集校验。
- **修法**：`buildUpdate` 与各 repo 动态 update 入口加列名白名单(`Set<String>` 或 `RegExp(r'^[a-z_][a-z0-9_]*$')`)，命中非法键抛 InkError。纯防御加固。

### S6-2 | P3 | [Correctness / 跨 S7 接缝] | `lib/storage/repositories/postgres_job_repository.dart:165-166` | `[需复核]`
`purgeExpired` 以 `j.completed_at < now() - (@days)::interval` 过滤。`completed_at IS NULL` 的终态行该谓词恒 NULL(永不为真)，**永不被时间保留清除**。核对所有终态跃迁：success/error/timeout/用户 cancel 都写了 completed_at(job_queue_service:393/498/515/530)，唯独**启动恢复**把孤儿 job 跃迁 `cancelled` 时**没写 completed_at**(job_queue_service:103-110) → 这些行 completed_at 永久 NULL，逃过 purgeExpired。仍被 `purgePerCanvasCap`(按 created_at 排名)兜底，故是**有上限的泄漏**非无限增长；根因在 S7 不在 S6。
- **修法**：(a) 推动 job_queue_service:107 的 cancel-on-restart extra 补 `completed_at`(治本，属 S7)；或 (b) S6 侧把谓词改 `COALESCE(j.completed_at, j.created_at) < now() - interval`。建议 (a)。

### S6-3 | info | [Security-posture，已文档化设计] | `lib/storage/pg_controller.dart:71-77,88-90` | `[已确证]`
嵌入式 PG 用 `initdb -A trust`(无口令本地 trust)。按铁律9查"口令进日志/明文连接串"——**全仓 lib/storage 无任何 password/secret 字面量或日志**(grep 仅命中注释 "trust")，**不存在口令泄漏面(压根没口令)**。监听面已正确收敛:`listen_addresses=127.0.0.1` + `unix_socket_directories=`(空，禁 socket)，无 0.0.0.0;日志只记 port。单用户桌面应用既定架构(PgController 头注释明示强制 127.0.0.1)，符合设计，**非违规**。仅记姿态:trust+loopback 意味同机任意本地进程可无凭据连库。
- **修法**：若日后引入多租户/远程，改 scram-sha-256 + 随机口令存 OS keychain;当前无需动作。

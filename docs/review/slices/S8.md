## Findings

### S8-1 | **P0** | [CI] | `.github/workflows/ci.yml:35-42`(及 :34) | `[已确证]`
CI 把 4+ 条铁律闸门(inline-styles/magic-strings/direct-instantiation/disposable，及 :34 i18n-coverage)以 `bash scripts/hooks/check-*.sh` **无文件参数**调用，而每个 check 开头 `[[ -z "$FILE" ]] && exit 0` 在无参时立即空转退出 0。结果这些铁律在 CI 里完全 no-op。
- **自证**：`bash scripts/hooks/check-inline-styles.sh` → exit 0 空输出(magic-strings/direct-instantiation/disposable 同)。
- **修法**：A) `git ls-files 'lib/**/*.dart' | xargs -I{} bash scripts/hooks/check-inline-styles.sh {}`，或让脚本支持无参=全量(照 check-updated-at.sh 双模式)。B)(更优)把规则做成 Dart 测试/custom_lint 进 test job。

### S8-2 | **P0** | [CI] | `scripts/hooks/check-i18n-coverage.sh:14` | `[已确证]`
第 14 行 `[[ "$FILE" == *.dart" ]]` 有未配对引号，`bash -n` rc=2 语法错误，带参崩、无参又提前 exit 0——i18n parity 闸门彻底死掉。
- **自证**：`bash -n …check-i18n-coverage.sh` → `line 14: syntax error`, rc=2;`cat -A` 第14行确认 `*.dart" ]]`。
- **修法**：改 `[[ "$FILE" == *.dart ]] && IS_DART=true`，并按 S8-1 让 CI 喂参/全量运行。

### S8-3 | P1 | [CI] | `scripts/hooks/pre-commit:24-27`(CHECKS 数组 :15-22) | `[已确证]`
本地 pre-commit 同款无参循环调用全部 6 check → inline-styles/magic-strings/direct-instantiation/disposable/i18n 在 commit 时也空转(仅 check-updated-at 因支持无参全量会真跑)。叠加：`git config core.hooksPath`=默认 `.git/hooks` 且无 pre-commit 安装，git 默认根本不触发。
- **修法**：pre-commit 改对 `git diff --cached --name-only --diff-filter=ACM` 暂存文件逐个喂参;并把 `git config core.hooksPath scripts/hooks` 写进 SETUP。

### S8-4 | P1 | [CI] | `.github/workflows/ci.yml:31-32` | `[已确证]`
pubspec(:67-68)声明 `custom_lint`+`riverpod_lint`、analysis_options(:1)注释宣称"custom_lint(Riverpod 规则)"，但 CI 只跑 `flutter analyze`，**从不 `dart run custom_lint`** → riverpod 规则零强制。
- **自证**：`grep -rn custom_lint .github/ scripts/` 无命中。
- **修法**：analyze job 增 `- run: dart run custom_lint`(退出码非零即失败)，放在 flutter analyze 后。

### S8-5 | P2 | [CI] | `scripts/hooks/check-updated-at.sh:38` | `[已确证]`
`python3 - "$f" … <<'PY' || VIOLATIONS+=("$f")`：无 python3 时 `||` 把每个文件塞进 VIOLATIONS，整脚本 exit 1 误报全红(fails-closed)。CI(ubuntu 有 python3)能跑;跨平台/精简镜像不可靠，且把"工具缺失"与"真违规"混为一谈。是**唯一**在 CI 真跑的 hook。
- **修法**：头部加 `command -v python3 >/dev/null || { echo "python3 missing" >&2; exit 1; }`;或改纯 bash/awk。

### S8-6 | P2 | [Secrets] | `scripts/pg/fetch-binaries.sh:90-98` | `[需复核]`
archive(:90)与其 `.sha256`(:91)从同一 `PG_ARTIFACT_BASE_URL` 拉取——能改 archive 者(被攻陷对象存储/MITM)可同步改 sha256，校验恒过。SHA256 在此威胁模型下只防传输损坏不防供应链篡改。
- **修法**：把每平台预期 SHA256 钉进仓库内文件，脚本只信仓内值;或对 archive 加 cosign/GPG 分离签名验签。

### S8-7 | P2 | [CI] | `secret-scan.yml:9` vs `ci.yml:12` | `[需复核]`
secret-scan push 触发 `[main, dev]`，ci 仅 `[main]`——直推 dev 跑 secret-scan 但不跑 ci(analyze/test)。PR 流程无缺口，但直推 dev 不过 CI 闸靠分支保护兜底。
- **修法**：统一两 workflow push 分支清单，并确保分支保护对 main/dev 都要求 CI 必过。

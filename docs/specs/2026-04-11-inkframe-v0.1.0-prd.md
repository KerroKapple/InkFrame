## 1. Product Vision

### What Is InkFrame

Open-source, local-first AI visual creation workstation for short drama and film production. Users bring their own API keys (BYOK), work entirely on desktop, and own all their data.

### Problem Statement

- Existing AI video creation tools are all web-based SaaS platforms that charge significant markup on API calls
- Web rendering is slow, laggy, and dependent on servers; data isn't in the user's hands
- Ordinary creators can't afford the cost; professionals find it expensive and restrictive
- AIGC feels inaccessible to regular people

### Core Proposition

- **Local-first** — Data stored in local embedded PostgreSQL; no server required; offline-capable (except AI generation API calls)
- **BYOK (Bring Your Own Key)** — Users provide their own official or third-party API keys; zero markup
- **Open-source & free** — MIT license, community-driven
- **Native experience** — Flutter Desktop, native rendering on macOS + Windows, no lag

### Target Users

- Independent creators (short dramas, short videos, social media content)
- Small studios (2-5 people, unable to afford SaaS fees)
- AIGC enthusiasts (want to try AI filmmaking but deterred by existing tool barriers)

### What InkFrame Is Not

- Not an online collaboration platform (v0.1.0 is purely local single-user)
- Not a video editing software (no timeline/NLE)
- Not a model training tool

## 2. Core User Scenarios

### Scenario 1: Image-to-Video Creation (P0 — Core Loop)

```
Create canvas → Add image node → Write prompt + select model + set params
→ Generate → Result outputs to new node → If satisfied, connect result to video node
→ Connection auto-transfers reference image → Configure video params (duration/camera)
→ Generate video (result outputs to new video node) → Preview/Download
```

User has a visual idea, generates an image first, iterates until satisfied, then generates a 5-second video from that image. Repeats for multiple shots.

### Scenario 2: Reference-Driven Batch Production (P0)

```
Drag local reference image onto canvas → Draw data connection to new image node
→ Write prompt describing variation → Generate style-consistent new image (to new node)
→ Connect to video node → Generate video
```

User has character design art, wants to generate different scenes/actions for the same character while maintaining style consistency.

### Scenario 3: Script-Driven Storyboard Production (P1)

```
Import/paste script text → AI parses script → Auto-split into Scene + Shot structure
→ Each Shot gets: narrative description + cinematography + 6-dimension analysis
→ System generates multi-grid prompt per Shot
→ Generate 9-grid/4-grid image (multiple keyframes in one image for consistency)
→ Auto-crop into individual keyframe images
→ User reviews on canvas: keep good ones, edit/regenerate bad ones
→ Drag approved keyframes into storyboard Shot node
→ Shot node: keyframes arranged horizontally + narrative prompt
→ Click "Generate Video" → multi-reference-image video generation (Kling/Seedance)
→ Video result displayed in Shot node → Preview on canvas
```

#### Storyboard Shot Node Design

```
+----------------------------------------------------------------------+
| Shot #1  "Character pushes door open"  Mid-shot / Push-in            |
| Narrative: Character slowly pushes heavy wooden door, dim interior   |
|                                                                      |
|  Keyframes (horizontal, add/remove):                     +--------+  |
|  +------+ +------+ +------+ +------+                    | Generate|  |
|  |Frame1| |Frame2| |Frame3| |Frame4|  ...               |  Video  |  |
|  +--+---+ +--+---+ +--+---+ +--+---+                    +--------+  |
|     |x       |x       |x       |x                                   |
|                                                                      |
|  Prompt: A man pushes open a heavy wooden door, dim interior...      |
|  Model: Kling 3.0 Multi-ref | Duration: 5s | Camera: Push-in        |
|                                                                      |
|  +--------------------+                                              |
|  | > Generated video   |                                             |
|  +--------------------+                                              |
+----------------------------------------------------------------------+
```

**Canvas-Storyboard Relationship:**
- Canvas = creative workspace (free image generation, 9-grid, editing, iteration)
- Storyboard = production pipeline (organize approved assets into shots, generate videos)
- Canvas image nodes can be referenced by multiple Shot nodes
- Keyframes in a Shot are references to canvas images, not copies
- Shots connected by narrative-order edges, visible on canvas
- Generated videos visible directly in Shot nodes on canvas

#### Multi-Grid Image Generation (Consistency Mechanism)

One Shot's content generates a single multi-grid image (4-grid or 9-grid), ensuring all keyframes share consistent style/character/lighting because they're produced in one generation pass.

Grid count scales with model capability: 4 → 9 → 16+

### Scenario 4: Asset Reuse and Management (P2)

```
Generate satisfactory character image → Right-click "Save as Asset"
→ Tag: name, type, trigger words
→ Later: new node → @mention that asset → Auto-inject reference + trigger words
→ Maintain character consistency across entire production
```

**Node context menu:** Edit, Copy, Copy as new version, Download, View original, Save as asset (P2), Add to storyboard (P1), Ignore zone style, Bring to front, Send to back, Delete.

**Edge context menu:** Reverse direction, Delete.

### 3.6 Toolbar Layout

**Left Dockbar (vertical icon buttons):** Add node (submenu: image/video/text), Style zone, Command bar.

Click creates node at viewport center. Can also drag from Dockbar to specific canvas position.

**Bottom-right:** Zoom percentage, Zoom in/out/fit buttons.

### 3.7 Canvas Background

| Property | Value |
|----------|-------|
| Background color | Dark theme: `#0F0F13` (InkColors.surface1) |
| Grid dots | Optional, 20px spacing, `#FFFFFF` at 5% opacity |
| Style lane tint | Semi-transparent overlay, 8-12% opacity |
| Boundary line | 40px gradient transition between lanes |

### 3.8 Keyboard Shortcut System

**All shortcuts are user-configurable.**

Shortcut config structure:
```
{
  "action_id": "canvas.select_all",
  "label": "Select All",
  "category": "canvas",
  "default_binding": "Cmd+A / Ctrl+A",
  "user_binding": null,
  "context": "canvas_focused"
}
```

Context isolation: different contexts (canvas_focused / node_selected / global) can share keybindings without conflict.

Conflict detection: prompts user to override or cancel on conflict.

Platform-aware: displays Cmd on macOS, Ctrl on Windows; stores using universal identifier (mod).

Persistence: `~/.inkframe/config/keybindings.json`

Settings page supports search, category browsing, key recording, reset to default.

### 3.9 Performance Tiers & User Preferences

Four presets + custom mode:

| Preset | Target |
|--------|--------|
| Power Saver | Old devices, minimize resource usage |
| Balanced (default) | Mainstream hardware |
| Performance | High-end computers |
| Ultra | Best quality, no resource limits |

Customizable dimensions: **Node rendering** (thumbnail quality, video preview, off-screen rendering, shadows, animations), **Canvas** (grid, lane backgrounds, anti-aliasing), **Edges** (line/bezier/flowing/particles), **Interaction** (drag feedback, zoom animation), **System** (max visible nodes, cache size, FPS cap, GPU acceleration, undo history depth).

**Auto-detection on first launch:** Checks RAM, GPU, CPU cores; recommends appropriate tier.

**Runtime dynamic degradation:** Auto-releases cache when memory > 80%, disables animations when FPS < 30, silently recovers when stable.

Persistence: `~/.inkframe/config/performance.json`

### 3.10 Node Label Position Customization

All label elements (name, model, ratio, status, etc.) position and visibility are customizable.

**Placement positions:** 9 inner anchor points + 8 outer anchor points + hidden.

**Visibility conditions:** Always / Hover / Selected / Hidden.

**Editing:** Settings → Node Label Layout → Drag-edit interface. Left panel: available elements list. Right panel: live preview node. Drag elements to preview anchor points with auto-snap. Preview supports simulated states (default/hover/selected).

**Built-in presets:** Minimal (default), Info-rich, Production mode. Users can save custom presets.

Persistence: `~/.inkframe/config/node_layout.json`

## 4. Image Node

### 4.1 Visual Rules

**Core principle: Image is always the visual hero. Text never obscures media content.**

**Default state:** Clean image, no text overlay. Node name at bottom-right outside, plain text with no background/border (default preset, customizable position).

**Hover state:** Connection ports appear (horizontal lanes: left-in/right-out; vertical lanes: top-in/bottom-out). Top-right shows action icons (menu + view original), small size.

**Selected state:** Highlight border + connection ports. Inline panel opens.

**Generating state:** Semi-transparent overlay + centered small circular progress indicator (percentage).

**Error state:** Red border + centered error icon + clickable retry.

**Empty state:** Dashed border + centered "Click to edit" text.

### 4.2 View Original

| Trigger | Behavior |
|---------|----------|
| Hover + click magnifier icon | Full-screen lightbox view |
| Right-click → View original | Same |
| Configurable shortcut (node selected) | Same |

Lightbox: dark semi-transparent background, original resolution, scroll-zoom, drag-pan, left/right arrows for grid siblings, download button, Escape to close.

### 4.3 Node State Machine

```
Create → idle → (user clicks generate) → generating → success / error / cancelled
                                                        ↓
                                                  error → (retry) → generating
```

Generated results always output to a new node. Original node stays unchanged.

### 4.4 Node Data Model

| Field | Type | Description |
|-------|------|-------------|
| id | String | Unique identifier |
| type | "image" | Node type |
| label | String | User-editable title |
| status | Enum | idle / uploading / generating / success / error / cancelled |
| prompt | String | Prompt text |
| negativePrompt | String? | Negative prompt |
| model | String | Model ID |
| aspectRatio | String | "1:1" / "16:9" / "9:16" / "4:3" / "3:4" / "21:9" |
| resolution | String | "720p" / "1080p" / "2K" / "4K" |
| seed | int? | Random seed |
| imageUrl | String? | Generated result local file path |
| thumbnailUrl | String? | Thumbnail path |
| sourceNodeId | String? | Which node generated this |
| isGridGeneration | bool | Whether this is a grid generation |
| gridType | String? | "2x2" / "3x3" / null |
| gridChildren | List\<String\>? | Cropped child node IDs |
| parentGridId | String? | Parent grid node ID (if cropped from grid) |
| batchResults | List\<BatchResult\>? | Batch generation results |
| error | String? | Error message |
| progress | double | Generation progress 0.0-1.0 |
| taskId | String? | Provider async task ID |
| text | String? | Text node content only |
| createdAt | DateTime | Created time |
| updatedAt | DateTime | Updated time |
| deletedAt | DateTime? | Soft-delete timestamp |
| position | Offset | Canvas coordinates (x, y) |
| size | Size | Node dimensions, fixed width, height adapts to image ratio |
| zIndex | int | Layer order, most recent operation auto-tops |

### 4.5 Generation Behavior

**Core principle: Generation results always output to a new node. Original node is never overwritten.**

Every node can have both prompt and imageUrl. Any node with a prompt can initiate generation. Result nodes inherit source node's prompt/model/params as snapshot. Users can modify result node params to iterate further.

**Auto-layout:** New result nodes placed 60px to the right of source, multiple results stack vertically.

### 4.6 9-Grid / 4-Grid Generation

User selects grid mode → generates one complete grid image (to new node) → click [Auto-crop to 9] → creates 9 child image nodes below parent → generation_source edges auto-created → user picks useful children.

Cropping: equal-division, children inherit parent prompt + position label, named `{parent}_1` through `{parent}_9`. Deleting parent prompts whether to delete children.

### 4.7 Drag-in Local Files

| Input | Behavior |
|-------|----------|
| Local image (png/jpg/webp) | Create image node, save to project dir, status: success |
| Multiple images | Create one node each, auto-arrange |
| From browser | Download locally, create node |
| Unsupported format | Toast notification |

## 7. Style Lane System

### 7.1 Core Concept

Canvas divided into style lanes — horizontal or vertical bands with distinct background tints and gradient boundary lines between them.

### 7.2 Data Model

| Field | Type | Description |
|-------|------|-------------|
| id | String | Unique identifier |
| label | String | Lane name |
| stylePrompt | String | Style description text |
| order | int | Sort order |
| tintColor | Color? | Background tint, null = auto-infer |
| size | double | Lane width (vertical) or height (horizontal) |

### 7.3 Lane Visuals

**Auto-tint from keywords:** warm/dusk/restaurant → warm orange; rain/night/neon → cool blue; fluorescent/office → cyan-white; forest/nature → deep green; horror/dark → deep purple. User can override with manual color.

**Boundary line:** 40px gradient transition + 1px thin line. Hover shows "+" button. Power saver mode degrades to solid line.

**Lane title bar:** Semi-transparent at lane top (horizontal) or left (vertical). Hover shows edit and menu buttons.

### 7.4 Style Injection Logic

```
Final prompt = project baseStylePrefix + lane stylePrompt + node prompt + project baseStyleSuffix
```

Inline panel shows real-time assembled preview at bottom.

### 7.5 Lane Operations

| Operation | Method |
|-----------|--------|
| Create | "+" on boundary / Dockbar button / First creation on empty canvas |
| Edit | Double-click title bar → edit popup (name, style description, background color) |
| Resize | Drag boundary line |
| Reorder | Drag title bar |
| Layout toggle | Toolbar button: horizontal / vertical |
| Collapse | Double-click boundary → collapse to title bar |
| Delete | Title bar menu, confirmation dialog |

### 7.6 Node-Lane Relationship

- Node center point determines which lane it belongs to
- Dragging across boundary → target lane highlights → ownership switches on drop
- Generated results unaffected; only next generation uses new style
- Nodes outside all lanes inherit project base style only
- Per-node toggle: "Ignore zone style"

### 7.7 Project Base Style

Top nav bar shows current base style, click to edit popup:
- Prefix input (prepended to all prompts)
- Suffix input (appended to all prompts)
- Quick presets: Live-action film / Chinese animation / Ghibli / Cyberpunk / Ink wash / Photography / 3D animation

### 7.8 What Style Zones Can Describe

Location, time, weather, lighting, mood, art style — completely free-form.

## 8. Edge System

### 8.1 Three Edge Types

| Type | Purpose | Visual | Creation |
|------|---------|--------|----------|
| **data** | Transfer data between nodes | Solid, blue | User manual drag |
| **narrative** | Shot narrative order (P1) | Solid, gold | User manual |
| **generation_source** | Config→result, grid→children | Thin, gray | System automatic |

### 8.2 Dynamic Adaptation of Data Edges

Edges only transfer data. Model capabilities determine usage.

Multiple images connected to same video node → inline panel adapts to model:
- Model supports multi-ref → all shown as reference images, sortable
- Model supports single-ref only → user picks one
- Model supports first/last frame → user can switch to frame mode
- Model doesn't support image input → reference area hidden, edges don't affect generation

### 8.3 Edge Creation Flow

Drag from port → snap to target → release → directly create data edge.

Exception: target is Shot node (P1) → popup to choose data or narrative. Only one possibility → no popup. generation_source is system-automatic only.

### 8.4 Edge Side Effects

| Event | Auto behavior |
|-------|---------------|
| Data edge into video node | Auto-switch to image-to-video mode |
| All data edges disconnected | Auto-revert to text-to-video mode |
| Delete node | Cascade disconnect all edges |

### 8.5 Edge Validation

No self-connections. No duplicates (same source + target + type). Narrative edges must be DAG (no cycles).

### 8.6 Edge Visuals

Default 30% opacity, hover 80%, selected 100%, related node selected 60%. During edge creation, other edges drop to 10%.

Rendering detail (line/bezier/flowing/particles) follows performance tier.

## 9. Inline Panel (Unified Spec)

### 9.1 Positioning & Appearance

- 740px wide, height auto-expanding (280px minimum)
- Positioned 16px below node, horizontally centered
- Small triangle pointing up to node
- Entry animation: 0.15s scale+fade
- Opens on single-click at any zoom level
- Fixed-size rendering, does not follow canvas zoom
- Hidden when multiple nodes selected (batch action bar shown instead)

### 9.2 Panel Layout

```
Reference image area (only when model supports AND content exists)
  OR First/last frame area (mutually exclusive, based on model + content)
Associated text labels (when text nodes connected via data edge)
Prompt input textarea (supports / slash commands and @ asset refs) + Enhance button
Bottom toolbar
```

### 9.3 Bottom Toolbar

Horizontal layout, auto-wrapping:

1. **Model selector** — only shows models matching node type; unconfigured keys labeled "Not configured"
2. **Quality/ratio** — popup: ratio button group + resolution [720p] [1080p] [2K] [4K]; unsupported options hidden
3. **Batch count** — shown when model supports: [1x] [2x] [4x]
4. **Duration** — video only + model supports; only shows supported options
5. **Camera movement** — video only + model supports; popup grid icon selection
6. **Advanced settings** — shown when model declares any advanced param (seed/negative/steps/cfg/sound)
7. **Generate button** — white, right-aligned, shows estimated token cost; disabled when no prompt

**Core principle: Unsupported capabilities are completely hidden — not grayed out, no space occupied. Smooth panel re-layout when switching models.**

### 9.4 Slash Commands

Type `/` or `、` to trigger command menu, positioned above textarea. Arrow keys navigate, Enter selects, type to filter.

Built-in: /grid-9, /grid-4, /lighting, /3view.

### 9.5 @ Asset Reference (P2, UI reserved)

Type `@` to trigger asset panel. Three top-level tabs: Characters / Assets (with Environment/Props sub-categories) / Canvas (current canvas image nodes). Selection auto-adds reference image + trigger words to prompt.

### 9.6 Keyboard Handling

Enter (no Shift) submits generation. Shift+Enter for newline. Escape closes panel. All keyboard events stopPropagation to prevent canvas shortcut conflicts.

## 10. Provider System

### 10.1 Provider Capability Declaration

Each Provider declares capabilities via ProviderCapabilities: modes, aspectRatios, resolutions, durations, maxRefImages, supportsFirstFrame, supportsLastFrame, supportsCameraMovement, supportsNegativePrompt, supportsSeed, supportsSound, supportsBatch, maxBatch.

Inline panel dynamically shows/hides parameters based on these declarations.

### 10.2 P0 Provider List

**Image:**

| Provider | ID | Region | Modes | Resolution | Ref images |
|---------|-----|--------|-------|------------|------------|
| Gemini Image | gemini-image | global | text-to-image | 1080p | 0 |
| Jimeng 4.5 | jimeng-4.5 | cn | text-to-image | 1080p, 2K | 1 |
| Kling Image | kling-image | cn | text-to-image, image-to-image | 1080p | 1 |

**Video:**

| Provider | ID | Region | Modes | Resolution | Duration | Camera | Audio |
|---------|-----|--------|-------|------------|----------|--------|-------|
| Kling 3.0 | kling-3.0 | cn | text-to-video, image-to-video | 1080p | 5s, 10s | Yes | No |
| Hailuo 2.3 | hailuo-2.3 | cn | text-to-video, image-to-video | 720p, 1080p | 4s, 8s | Limited | No |

P1 adds: Kling 3.0 multi-ref, Seedance 2.0.
P2 adds: Sora, Veo 3.1 (with audio), Wanx.

### 10.3 Unified Generation Flow

```
Param validation → Style injection (assemble prompt) → Reference image processing
→ Create result node (status: generating) + generation_source edge
→ Submit to Provider API → Poll (3-5s interval, 30-minute timeout)
→ Success: download locally + generate thumbnail + update node
→ Failure: update node error field + Toast notification
```

### 10.4 Error Handling

| Error Type | User Message |
|-----------|-------------|
| Key not configured | Redirect to settings |
| Key invalid | Redirect to settings |
| Insufficient balance | Show provider name |
| Content moderation rejection | Prompt to modify |
| Network timeout | Check network |
| Provider service error | Retry later |
| Polling timeout | Service may be busy |

### 10.5 Proxy Configuration

Settings → Network: System proxy / Manual config / No proxy. Supports per-Provider override (different providers can use different proxies).

Models returning video with audio track: audio preserved as-is. Export project files split video to V1 track, audio to A1 track.

### 13.6 metadata.json

Contains version, export time, project name, canvas name, sort mode, per-clip: index, filename, label, duration, resolution, audio flag, prompt, model, generation time.

## 14. Delete & Recycle Bin

### 14.1 Delete Behavior

All delete operations (nodes, edges, lanes, canvases, projects) go to recycle bin first. Database marks `deleted_at` timestamp.

Node delete requires no confirmation (supports undo). Canvas delete requires confirmation dialog. Project delete requires typing name to confirm.

### 14.2 Recycle Bin

Per-project independent recycle bin. Entry: Settings → Storage → Open Recycle Bin.

Grouped by date, supports per-item restore/permanent delete, clear all. Shows space usage.

Restore logic: restore to original location; if parent object is deleted, prompt to restore parent first.

### 14.3 Auto-Cleanup

Recycle bin retains 30 days by default (configurable). Auto-permanently-deletes on expiry. Permanent delete removes database rows and filesystem files.

## 15. Cache System

### 15.1 Thumbnail System

**Generation triggers:** Image generation success, video generation success (extract first frame), drag-in local files, grid cropping.

**Four tiers:** micro (64px), small (128px), medium (256px), large (512px), JPEG format.

**Per performance tier:** Power saver→small, Balanced→medium, Performance→large, Ultra→original.

### 15.2 Memory Cache (LRU)

| Parameter | Power Saver | Balanced | Performance | Ultra |
|-----------|-------------|----------|-------------|-------|
| Max cached | 30 | 80 | 150 | 300 |
| Est. memory | ~50MB | ~150MB | ~300MB | ~600MB |

LRU eviction, prioritizing off-screen nodes. Load priority: in-viewport > 1-screen out > 2-screens out.

### 15.3 Off-Screen Node Rendering

In-viewport renders normally, off-screen progressively degrades by distance and performance tier: thumbnails → placeholder (color block + title) → not rendered.

Zoom < 30%: all nodes degrade to placeholders.

### 15.4 Cache Cleanup

Source file permanently deleted → clean up corresponding thumbnails. Disk over limit → evict oldest. Startup scans orphaned thumbnails.

Settings → Storage shows and manages cache, configurable thumbnail cache limit.

## 16. Undo/Redo Mechanism

### 16.1 Operation Stack

Dual stack (undo + redo), per-canvas independent, depth follows performance tier (20-200), not persisted.

### 16.2 Undoable Operations

Create/delete/move nodes, edit prompt/params, create/delete edges, create/edit/delete lanes, edit text nodes, grid cropping.

### 16.3 Non-Undoable Operations

Initiating generation (consumes API credits). Permanent delete (clear recycle bin).

### 16.4 Redo Stack Clear

Any new operation after undo → redo stack cleared.

## 27. Crash Recovery

### 27.1 Protection Mechanisms

| Mechanism | Description |
|-----------|-------------|
| Auto-save | Every 5s (configurable) to PostgreSQL |
| Crash marker | Writes `~/.inkframe/.running` on launch, deletes on clean exit |
| Log files | `~/.inkframe/logs/inkframe.log`, retains last 7 days |

### 27.2 Detection & Recovery

On launch, checks for `.running` file → exists = last session crashed → recovery dialog:

```
⚠ InkFrame did not exit normally last time
Last opened canvas: "Episode 1"
Last saved: 12:35:20

[Restore last state]    [Start from project list]
```

Restore: opens last canvas, restores viewport. Data intact (auto-saved).

### 27.3 Logs

```
~/.inkframe/logs/
├── inkframe.log          ← Current
├── inkframe.log.1        ← Yesterday
└── ...                   ← Max 7 days
```

Records: start/stop, generation tasks, uncaught exceptions, Provider API errors (no keys logged).

Settings → About: `📋 Log directory [Open folder]`

## 1. 产品愿景

### InkFrame 是什么

开源、本地优先的 AI 影视创作工作站，面向短剧和影视制作。用户使用自己的 API Key（BYOK），完全在桌面端工作，数据完全归自己所有。

### 要解决的问题

- 现有 AI 视频创作工具全是 Web 端 SaaS 平台，API 调用赚大量差价
- Web 端渲染慢、卡顿，依赖服务器，数据不在用户手中
- 普通创作者用不起，专业人士觉得贵且受限
- AIGC 对普通人来说感觉高高在上、触不可及

### 核心主张

- **本地优先** — 数据存储在本地嵌入式 PostgreSQL，无需服务器，离线可用（AI 生成 API 调用除外）
- **BYOK（自带密钥）** — 用户填写官方或三方 API Key，零差价
- **开源免费** — MIT 协议，社区驱动
- **原生体验** — Flutter Desktop，macOS + Windows 原生渲染，不卡顿

### 目标用户

- 独立创作者（短剧、短视频、自媒体内容）
- 小团队工作室（2-5 人，无力承担 SaaS 费用）
- AIGC 爱好者（想尝试 AI 影视创作，但被现有工具门槛劝退）

### InkFrame 不是什么

- 不是在线协作平台（v0.1.0 纯本地单机）
- 不是视频剪辑软件（没有时间线/NLE）
- 不是模型训练工具

## 2. 核心用户场景

### 场景 1：从生图到生视频（P0 — 核心闭环）

```
创建画布 → 添加图片节点 → 写 prompt + 选模型 + 设参数
→ 生成 → 结果输出到新节点 → 满意则从结果节点拖出连线到视频节点
→ 连线自动传递参考图 → 配置视频参数（时长/运镜）
→ 生成视频（结果输出到新视频节点）→ 预览/下载
```

用户有个画面想法，先生成一张图，迭代到满意，再基于这张图生成一段 5 秒视频。反复多组镜头素材。

### 场景 2：参考图驱动批量生产（P0）

```
拖入本地参考图到画布 → 从参考图拉 data 连线到新图片节点
→ 写 prompt 描述变化 → 生成保持风格一致的新图（输出到新节点）
→ 连到视频节点 → 生成视频
```

用户已有角色设定图，想基于同一角色生成不同场景/动作的图片，保持风格一致性。

### 场景 3：剧本驱动分镜生产（P1）

```
导入/粘贴剧本文本 → AI 解析剧本 → 自动拆分为 场景(Scene) + 镜头(Shot) 结构
→ 每个 Shot 获得：叙事描述 + 镜头语言
→ 系统为每个 Shot 生成多宫格 prompt
→ 生成九宫格/四宫格图（一张图内多个关键帧，天然保持一致性）
→ 自动裁切为独立关键帧图片
→ 用户在画布上审查：满意的保留，不满意的编辑/重新生成
→ 把通过的关键帧拖入分镜 Shot 节点
→ Shot 节点：关键帧横向排列 + 叙事 prompt
→ 点击"生成视频" → 多参考图生视频（Kling/Seedance）
→ 视频结果显示在 Shot 节点内 → 画布上可预览
```

#### 分镜 Shot 节点设计

```
+----------------------------------------------------------------------+
| Shot #1  "主角推门进入"  中景·推镜头                                   |
| 叙事: 主角缓步推开沉重的木门，室内昏暗，逆光剪影                        |
|                                                                      |
|  关键帧（横向排列，可增减）：                            +--------+   |
|  +------+ +------+ +------+ +------+                   | 生成   |   |
|  | 帧1  | | 帧2  | | 帧3  | | 帧4  |  ...              | 视频   |   |
|  |      | |      | |      | |      |                   |        |   |
|  +--+---+ +--+---+ +--+---+ +--+---+                   +--------+   |
|     |x       |x       |x       |x                                   |
|                                                                      |
|  提示词: A man pushes open a heavy wooden door, dim interior...      |
|  模型: Kling 3.0 多图参考 | 时长: 5s | 运镜: 推                      |
|                                                                      |
|  +--------------------+                                              |
|  | > 生成的视频预览    |                                              |
|  +--------------------+                                              |
+----------------------------------------------------------------------+
```

**画布与分镜的关系：**
- 画布 = 创作空间（自由生图、九宫格、编辑、迭代）
- 分镜 = 生产线（把画布里 OK 的素材组织起来生成视频）
- 画布上的图片节点可以被多个 Shot 节点引用
- Shot 里的关键帧是画布图片的引用，不是复制
- Shot 之间通过叙事顺序连线连接，在画布上可见
- 生成的视频直接显示在画布上的 Shot 节点内

#### 多宫格生图（一致性保障机制）

每个 Shot 的内容生成一张多宫格图（四宫格或九宫格），因为在同一张图中生成，天然保证所有关键帧的风格/角色/光照一致。

```
九宫格生成 → 自动裁切 → 9 张独立关键帧图片
→ 用户保留有用的，删掉/编辑不好的
→ 通过的关键帧添加到 Shot 节点作为视频参考图
```

宫格数量随模型能力提升而增加：4 → 9 → 16+

### 场景 4：资产复用与管理（P2）

```
生成满意的角色图 → 右键"保存为资产"
→ 标注：名称、类型、触发词
→ 后续：新节点 → @提及该角色资产 → 自动注入参考图 + 触发词
→ 保持整部作品角色一致性
```

### 3.7.1 主题系统对齐

**P0 颗粒度：**
- 设置 → 常规"主题"选项：`深色 / 浅色 / 跟随系统`，三个都**显示**

```dart

  factory InkColors.dark()  => const InkColors._(surface1: Color(0xFF0F0F13), ...);
  factory InkColors.light() => const InkColors._(surface1: Color(0xFFFAFAFA), ...);
  factory InkColors.highContrast() => const InkColors._(...);  // A11y §20.1

```

### 3.9 性能档位与用户偏好系统

四个预设 + 自定义模式：

| 预设 | 定位 |
|------|------|
| 省电 | 老设备，最大限度降低资源占用 |
| 均衡（默认） | 主流配置，平衡画质和性能 |
| 性能 | 高配电脑，更好的视觉效果 |
| 极致 | 最佳画质，不限制资源 |

可自定义的参数维度：

**节点渲染：** 缩略图质量（128/256/512/原图）、视频预览（首帧/悬停播放/自动播放）、离屏节点渲染（不渲染/简化/完整）、节点阴影（关/简单/柔和/多层）、节点动画（关/状态切换/全部/粒子）

**画布：** 背景网格（关/点阵/点阵+线）、风格泳道背景（纯色/渐变/渐变+模糊）、抗锯齿（关/基础/2x/4x）

**连线：** 渲染（直线/贝塞尔/流动/粒子）

**交互：** 拖拽反馈（无/影子/高亮/吸附动画）、缩放动画时长（0-350ms）

**系统：** 最大可见节点数（50-无限）、缩略图缓存大小（100MB-1GB）、渲染帧率上限（30/60/不限）、GPU 加速（关/基础/完整）、撤销历史步数（20-200）

**性能档位完整默认值：**

| 参数 | 极致 | 性能 | 均衡 | 省电 |
|------|------|------|------|------|
| 画布最大节点数 | 500 | 300 | 150 | 80 |
| 过渡动画 | 开 | 开 | 关 | 关 |
| 节点阴影 | 多层 | 柔和 | 简单 | 关 |
| 抗锯齿 | 4x | 2x | 基础 | 关 |
| 缩略图分辨率 | 原图 | 512 | 256 | 128（JPEG 质量 80） |
| 撤销历史步数 | 200 | 100 | 50 | 20 |
| 视口外预加载半径（屏） | 3 | 2 | 1 | 0 |
| 帧率上限 | 不限 | 60 | 60 | 30 |
| 模糊/毛玻璃 | 开 | 开 | 关 | 关 |
| 最大并发生成任务 | 4 | 3 | 2 | 1 |
| 背景网格 | 点阵+线 | 点阵 | 点阵 | 关 |
| 连线渲染 | 粒子 | 流动 | 贝塞尔 | 直线 |
| 缩略图内存缓存 | 300 | 150 | 80 | 30 |

对应 Dart 定义见 `lib/core/constants/performance.dart`。

**首次启动自动检测：** 检测内存、GPU、CPU 核心数，推荐合适档位。

**运行时动态降级：** 内存 > 80% 自动释放缓存，帧率 < 30fps 自动关闭动画，恢复后静默恢复设置。

持久化：`~/InkFrame/config/performance.json`

### 3.9.1 首次启动档位推荐算法

```dart
PerformanceTier recommend(DeviceProfile d) {
  // 极致：专业设备
  if (d.ramGB >= 32 && d.hasDedicatedGPU && d.cpuCores >= 8) return ultimate;
  // 性能：主流高配
  if (d.ramGB >= 16 && (d.hasDedicatedGPU || d.isAppleSilicon) && d.cpuCores >= 6) return performance;
  // 省电：老设备兜底
  if (d.ramGB < 8 || d.cpuCores < 4) return eco;
  // 默认均衡
  return balanced;
}
```

**DeviceProfile 采集来源：**
- `ramGB`：`sysctl hw.memsize` (macOS) / `GlobalMemoryStatusEx` (Windows)
- `cpuCores`：`Platform.numberOfProcessors`
- `hasDedicatedGPU`：macOS 查 `system_profiler SPDisplaysDataType`；Windows 查 `WMI Win32_VideoController`
- `isAppleSilicon`：`Platform.version.contains('arm64')`

用户可在首次引导二次确认或覆盖推荐值，持久化后不再自动重算。

### 3.9.2 运行时动态降级

**触发与恢复（Hysteresis 防抖动）：**

| 信号 | 降级触发 | 降级动作 | 恢复触发 | 恢复动作 |
|------|---------|---------|---------|---------|
| 内存 | RSS > 80% 持续 10s | 清 LRU 至 50%、缩略图缓存减半 | RSS < 60% 持续 30s | 静默恢复 |
| 帧率 | FPS < 30 持续 5s | 关动画、连线降级为直线、禁用模糊 | FPS > 55 持续 30s | 静默恢复 |
| 磁盘 | 剩余 < 1GB | 停止所有生成、Toast 警告 | 剩余 > 5GB | 自动解除生成禁用 |

**冷却期：** 每次降级/恢复后 60s 内不再触发同向动作，防反复抖动。

**用户控制：** 设置 → 性能新增 `☐ 启用运行时自动降级`（默认开）；关闭后遇到阈值仅 Toast 提示，不改变运行时参数。

**可观测性：** 降级事件以 `WARN` 级别入日志，字段 `extra: { signal, before, after, trigger_ms }`。

### 3.10 节点标签位置自定义

所有标签元素（名称、模型、比例、状态等）的位置和显示条件可自定义。

**可放置位置：** 内侧 9 个锚点 + 外侧 8 个锚点 + 隐藏。

**显示条件：** 始终显示 / 悬停显示 / 选中显示 / 隐藏。

**编辑方式：** 设置 → 节点标签布局 → 拖拽编辑界面。左侧可用元素列表，右侧实时预览节点。拖拽元素到预览节点的锚点上，自动吸附。预览区可切换模拟状态（默认/悬停/选中）。

**内置预设：** 极简（默认）、信息丰富、制片模式。用户可保存自定义预设。

持久化：`~/InkFrame/config/node_layout.json`

### 3.11 zIndex 管理规则

**写入：** 任一节点被选中/拖拽/编辑完成时，触发 `bringToFront(nodeId)`：

```
newZ = (SELECT MAX(z_index) FROM nodes WHERE canvas_id=? AND deleted_at IS NULL) + 1
UPDATE nodes SET z_index = newZ WHERE id=?
```

**重整（compaction）：** 当 `MAX(z_index) > 1_000_000`（兜底防溢出）时触发一次性重整：

```sql
WITH ranked AS (
  SELECT id, ROW_NUMBER() OVER (ORDER BY z_index ASC) AS rn
  FROM nodes WHERE canvas_id = $1 AND deleted_at IS NULL
)
UPDATE nodes SET z_index = ranked.rn FROM ranked WHERE nodes.id = ranked.id;
```

重整在自动保存事务内执行，用户无感。

**置顶/置底（§3.5 右键菜单）：**
- 置顶 = `bringToFront`
- 置底 = `z_index = MIN - 1`（同样可能触发负向重整）

**多选批量移动：** 不改 `z_index`，保持相对层级；仅"批量置顶"菜单触发时，按当前 `z_index` 升序依次 `bringToFront`。

**新建节点：** 初始 `z_index = MAX + 1`，自动置顶。

**九宫格子节点：** 裁切时 9 个子节点一次性分配连续的 `z_index`（父节点 `z_index - 1` 起往下），与父节点相邻但在其下层，避免覆盖父节点缩略图。

## 4. 图片节点

### 4.1 节点视觉规则

**核心原则：图片永远是视觉主体，文字信息不遮挡媒体内容。**

**默认状态：** 纯净图片，无任何文字覆盖。节点名称在右下角外侧，纯文字无背景无边框（默认预设，可自定义位置）。

**悬停状态：** 连接点出现（横向泳道：左入右出；竖向泳道：上入下出）。右上角浮出操作图标（菜单 + 查看原图），小尺寸不遮挡。

**选中状态：** 高亮边框 + 连接点。弹出内联面板。

**生成中状态：** 半透明蒙层 + 居中小型圆形进度指示器（百分比）。

**错误状态：** 红色边框 + 居中错误图标 + 可点击重试。

**空状态：** 虚线边框 + 居中"点击编辑"文字。

### 4.2 查看原图

| 触发方式 | 行为 |
|---------|------|
| 悬停时点击放大镜图标 | 全屏灯箱查看原图 |
| 右键 → 查看原图 | 同上 |
| 可配置快捷键（节点选中时） | 同上 |

灯箱功能：暗色半透明背景、原始分辨率显示、滚轮缩放、拖拽平移、九宫格子图可左右切换同组图片、下载按钮、Escape 关闭。

### 4.3 节点状态机

**config 节点（node_role = config）：** 只有 `idle` 一个状态，不参与生成。

**result 节点（node_role = result）：** 完整状态机如下：

```
creation
  ↓
generating ──► uploading ──► submitted ──► polling ──► success  (终态)
     │             │              │            │    ╲
     │             │              │            │     ╲─► timeout (终态)
     │             ▼              ▼            ▼
     └──────► error ◄─────────────┴────────────┘
                │                              │
                └──► generating（重试）         │
                │                              │
                └──► idle（用户放弃，reset）    │
                                               ▼
     所有非终态 ─────────────────────► cancelled (终态)
```

**状态定义：**

| 状态 | 含义 | 是否终态 |
|------|------|---------|
| generating | 已创建，正在准备提交 | 否 |
| uploading | 参考图上传中（仅当本地参考图需要上传） | 否 |
| submitted | 已提交 provider，未开始执行 | 否 |
| polling | provider 执行中，轮询查询 | 否 |
| success | 生成成功，文件已下载 | 是 |
| error | 失败（可重试） | 否（可转 generating 或 idle） |
| timeout | 30 分钟超时（视为 error 处理） | 是 |
| cancelled | 用户取消或 app 退出时强制取消 | 是 |

**cancelled 触发条件：**
1. 用户在面板点"取消"按钮
2. 应用正常退出时，所有非终态任务 graceful cancel（写入 DB 后再退出）
3. 用户永久删除节点（清回收站）时，关联未完成任务 cancel

### 4.5 生成行为规则

**核心原则：生成结果永远输出到新节点，原节点不被覆盖。**

```
[节点A] ──generation_source──→ [节点B]（新建，承载结果）
 (保持原样)                     (继承 A 的 prompt/模型/参数快照)
```

**节点角色不可变：**
- 只有 `node_role = config` 的节点可以发起生成
- `node_role = result` 的节点**严格只读**，面板只展示参数快照，不可编辑 prompt/参数
- 想基于结果再次迭代 → 点"派生新节点"创建新的 config 节点（见 §9.7）

**自动布局：** 新节点自动放置在源节点右侧 60px，多个结果节点竖向排列。

### 4.5.1 原配置节点删除后的 result 节点行为（孤儿）

**场景：** `source_node_id ON DELETE SET NULL`，原 config 节点被**永久删除**（清回收站）后，所有基于它生成的 result 节点 `source_node_id = NULL`，变成孤儿。

**孤儿 result 节点行为：**

| 能力 | 行为 |
|------|------|
| 节点渲染 | 正常显示图片/视频 + 参数快照（快照从 `jobs.parameters` 读取，不依赖源节点） |
| 面板顶部"由 {源节点名称} 生成" | 改显"来源节点已删除"，不可跳转 |
| 派生新节点 | **仍可派生** — 新节点 `source_node_id = NULL`（真正的独立节点），参数从 `jobs.full_prompt / parameters` 快照恢复 |
| 下载、查看原图、保存为资产 | 全部保留 |
| 被其他 result 节点的派生链引用 | 不受影响，派生链按 `jobs.source_node_id` 追溯 |

**参数快照来源优先级：**

```
1. 源 config 节点（若存在）的 type_config
2. jobs.parameters + jobs.full_prompt（兜底，永不丢）
3. 兜底失败 → 面板显示"参数已丢失"，禁用派生按钮
```

**owner 意识：** jobs 表是唯一真相源，result 节点面板必须能从 jobs 表单独还原，不依赖源节点存活。§21 的 30 天 retention 需联动调整（见 §21 Jobs 清理策略）。

### 4.6 九宫格/四宫格生成

```
用户选择"九宫格 3×3"模式 → 生成一张完整九宫格大图（输出到新节点）
→ 新节点显示完整九宫格 → 点击[自动裁切为 9 张]
→ 创建 9 个子图片节点，自动排列在父节点下方
→ 父 → 子之间自动创建 generation_source 连线
→ 用户挑选满意的子图做后续使用
```

**裁切规则：**
- **等分裁切**：按 `grid_type`（"2x2" / "3x3"）做等分切割，不检测分隔线
- **等分失败**（图片宽高不能被整除）：原图保留不裁，提示用户"宫格生成尺寸异常，已保留原图"
- **子节点命名**：`{父标题}_1` ~ `{父标题}_9`，继承父节点 prompt + 位置标注
- **父节点保留**：裁切后父节点保留（作为历史快照），缩略图显示原始宫格大图

**删除级联规则：**

| 操作 | 父节点行为 | 子节点行为 | `grid_children` |
|------|-----------|-----------|----------------|
| 删除子节点 | 不变 | 进回收站 | JSONB 同步移除该 id |
| 删除父节点 | 进回收站 | `parent_grid_id` 置 NULL，变为独立图片节点 | — |
| 永久删除父节点 | 物理删除 | 同上（已独立，不连带删除） | — |

### 4.6.1 九宫格字段组合矩阵

| 场景 | node_role | is_grid_generation | grid_type | grid_children | parent_grid_id |
|------|-----------|---------------------|-----------|---------------|----------------|
| 配置节点请求九宫格生成 | config | true | "3x3" / "2x2" | `[]` | null |
| 配置节点普通生成 | config | false | null | `[]` | null |
| 结果节点（九宫格大图） | result | true | "3x3" / "2x2" | 裁切后填入子节点 id 列表 | null |
| 结果节点（普通生成） | result | false | null | `[]` | null |
| 裁切产生的子节点 | result | false | null | `[]` | 父九宫格节点 id |
| 批量生成的 slot 结果 | result | false | null | `[]` | null |

**强约束：**
- `parent_grid_id IS NOT NULL` 蕴含 `is_grid_generation = false AND grid_children = []`（子节点不能再嵌套九宫格）
- `grid_children` 非空蕴含 `is_grid_generation = true AND node_role = 'result'`
- `is_grid_generation = true` 蕴含 `grid_type IS NOT NULL`

DB CHECK 约束（落 schema v=1）：

```sql
ALTER TABLE nodes ADD CONSTRAINT chk_grid_consistency CHECK (
  (type_config->>'parent_grid_id' IS NULL)
  OR (
    (type_config->>'is_grid_generation')::bool = false
    AND jsonb_array_length(COALESCE(type_config->'grid_children','[]'::jsonb)) = 0
  )
);
```

| 拖入内容 | 行为 |

| 多个图片文件 | 每个创建一个节点，自动排列 |

## 6. 文本节点

### 6.1 用途

存放文本内容（剧本片段、描述、备注），通过 data 连线传递给图片/视频节点作为关联 prompt。

### 6.2 外观

默认状态直接显示文本内容，无边框装饰。节点名称在右下角外侧。双击进入编辑模式，直接在节点内编辑文本。

### 6.3 数据模型

复用 nodes 表，type = `"text"`。`type_config` JSONB 仅含 `text` 字段，其余字段（prompt/image_url/video_url 等）不存在于该类型的 type_config 中。

### 6.4 连线行为

文本节点通过 data 连线连到图片/视频节点后：
- 目标节点内联面板顶部显示关联文本标签
- 生成时文本拼接到 prompt 中（风格注入之后、用户 prompt 之前）

```
最终 prompt = 项目基底前缀 + 泳道风格 + 关联文本 + 用户 prompt + 项目基底后缀
```

## 7. 风格泳道系统

### 7.1 核心概念

画布划分为风格泳道——横向或纵向的色带，每个泳道有独立背景色调和风格描述，泳道之间是渐变分界线。

### 7.2 数据模型

> 物理存储见 §21 `style_lanes` 表 DDL。

| 字段 | 类型 | 说明 |
|------|------|------|
| id | UUID | 唯一标识 |
| canvas_id | UUID | 所属画布 |
| label | String | 泳道名称 |
| style_prompt | String | 风格描述文本 |
| sort_order | int | 排列顺序 |
| tint_color | String? | 背景色调 hex（如 `#FF8A50`），null 时自动推断 |
| size | Real | 泳道宽度（竖向）或高度（横向），单位 px |

### 7.3 泳道视觉

**背景色自动推断：**

| 关键词 | 色调 |
|--------|------|
| 暖/黄昏/餐厅/烛光 | 暖橙 |
| 雨/夜/冷/霓虹 | 冷蓝 |
| 荧光/白/医院/办公 | 青白 |
| 森林/自然/草地 | 深绿 |
| 恐怖/暗/废墟 | 深紫 |

**推断规则：**
- 每组关键词维护中英双语列表，同义英文词参与匹配
- **多关键词命中**：取第一个命中的组（按表中定义顺序），不叠加
- 用户手动覆盖选色后，修改 `style_prompt` **不再重新触发推断**，用户色值优先级最高
- 用户可点"重置为自动"恢复推断

**定位：** 辅助功能，不是核心。推断不准不影响生成，用户手动改即可。

**分界线：** 两个泳道之间 40px 渐变过渡带 + 1px 细线。悬停分界线时显示 "+" 按钮。性能省电模式降级为纯实线。

**泳道标题栏：** 泳道顶部（横向）或左侧（竖向），半透明背景条。悬停显示编辑和菜单按钮。

### 7.4 风格注入逻辑

**唯一确定的拼接公式（与 §6.4 对齐）：**

```
final_prompt =
    baseStylePrefix                      // 项目基底前缀
  + laneStylePrompt                      // 归属泳道 style_prompt（无泳道为空）
  + associatedTexts                      // 所有连入文本节点内容，按 edge.created_at 升序，用 ", " 拼接
  + userPrompt                           // 节点自身 prompt
  + baseStyleSuffix                      // 项目基底后缀
```

**拼接细节：**
- 段间分隔符：`, `（英文逗号 + 空格），除非上一段本身以标点结尾
- 空段跳过（避免多余逗号）
- 多文本节点连入：按连线 `created_at` 升序拼接，用 `, ` 分隔
- `isIgnoreLaneStyle = true` 时 `laneStylePrompt` 为空

内联面板底部实时显示完整拼接预览。

## 8. 连线系统

### 8.1 三种连线类型

| 类型 | 用途 | 视觉 | 创建方式 |
|------|------|------|---------|
| **data** | 节点间传递数据 | 实线，蓝色 | 用户手动拖拽 |
| **narrative** | Shot 间叙事顺序（P1） | 实线，金色 | 用户手动 |
| **generation_source** | 配置→结果、九宫格→子图 | 细线，灰色 | 系统自动 |

### 8.2 data 连线的动态适应

连线只管传数据，模型能力决定怎么用。

多张图连入同一视频节点时，内联面板根据模型能力动态展示：
- 模型支持多图参考 → 全部作为参考图，可排序
- 模型只支持单图 → 用户选择其中一张
- 模型支持首尾帧 → 用户可切换为首尾帧模式，从连入图中选
- 模型不支持图片输入 → 参考图区域隐藏，连线不影响生成

### 8.3 连线创建流程

从连接点拖出 → 靠近目标吸附 → 松手 → 直接创建 data 连线。

从出连接点拖到空白区域 → 自动创建配置节点，并建立 `data` 连线（自动传递参考图）。

**默认节点类型（基于源节点推断）：**

| 源节点类型 | 默认新节点类型 |
|-----------|---------------|
| image | image |
| video | video |
| text | image |

创建后立即弹出节点类型选择 popover（image / video / text），用户可切换。

特殊情况：目标是 Shot 节点（P1）时弹出选择 data 或 narrative。只有一种可能时不弹选择。generation_source 由系统自动创建，用户不可手动创建。

### 8.4 连线副作用

| 事件 | 自动行为 |
|------|---------|
| data 连入视频节点 | 自动切换为图生视频模式 |
| 所有 data 断开 | 自动切回文生视频模式 |
| 删除节点 | 级联断开所有连线 |

### 8.5 连线验证

不允许自连接。不允许重复（同源同目标同类型）。narrative 不允许成环（必须是 DAG）。

### 8.6 连线视觉

默认低透明度（30%），悬停 80%，选中 100%。关联节点选中时 60%。拖拽连线中其他连线降到 10%。

具体渲染效果（直线/贝塞尔/流动/粒子）跟随性能档位。

## 9. 内联面板（统一规格）

### 9.1 定位与外观

- 宽 740px，高度自适应（280px 起）
- 位于节点正下方 16px，水平居中
- 顶部小三角指向节点
- 入场动画 0.15s 缩放+淡入
- 单击节点弹出；**画布缩放 < 30% 时不显示面板**（淡出 200ms）
- 面板固定尺寸渲染，不跟随画布缩放
- **溢出处理：** 面板超出视口边缘时自动调整位置——水平溢出则向反方向偏移，垂直溢出（节点在画布底部）则面板翻转到节点上方，小三角指向同步翻转。面板始终保持至少 16px 视口内边距。
- 多选时隐藏面板，显示批量操作栏

### 9.2 面板布局

```
参考图区域（仅模型支持且有内容时显示）
  或 首尾帧区域（互斥，根据模型能力和内容切换）
关联文本标签（从文本节点连入时显示）
提示词输入框（支持 / 斜杠命令和 @ 资产引用）+ 优化按钮
底部工具栏
```

### 9.3 底部工具栏

横向排列，自动换行：

1. **模型选择器** — 只显示当前节点类型匹配的模型，未配 Key 的标"未配置"
2. **画质/比例** — 弹窗：比例按钮组 + 分辨率 [720p] [1080p] [2K] [4K]，模型不支持的不显示
3. **批次** — 模型支持时显示 [1x] [2x] [4x]
4. **时长** — 仅视频 + 模型支持时，只显示支持的选项
5. **运镜** — 仅视频 + 模型支持时，弹窗网格图标选择
6. **高级设置** — 模型声明了任意高级参数时显示（种子/反向提示词/Steps/CFG/音频开关）
7. **生成按钮** — 白底右对齐，显示预估 Token 消耗，无 prompt 时灰掉

**核心原则：模型不支持的能力完全隐藏，不灰掉，不占空间。切换模型时面板平滑重排。**

### 9.4 斜杠命令

输入 `/` 或 `、` 触发命令菜单，内联定位在输入框上方。方向键导航，回车选择，输入过滤。

预置命令：/grid-9 九宫格、/grid-4 四宫格、/lighting 补光、/3view 三视图。

### 9.5 @ 资产引用（P2，面板预留）

输入 `@` 触发资产面板。三个一级 Tab：人物 / 资产（含环境/道具二级分类）/ 画布（当前画布图片节点）。选中后参考图自动加入 + 触发词拼入 prompt。

### 9.6 键盘操作

Enter（无 Shift）提交生成，Shift+Enter 换行，Escape 关闭面板。所有键盘事件 stopPropagation 防触发画布快捷键。

### 9.6.1 IME 输入法组合态处理

**问题：** 中文用户拼音选词时按 Enter 会意外触发生成。

**规则：**
- 监听 `TextInputConnection` 的 `composing` 区间
- `composing.isValid == true` 时，Enter 仅提交候选词，**不**触发 onSubmit
- 组合结束后第一个 Enter 才触发生成

```dart
void _onSubmit(TextEditingValue v) {
  if (v.composing.isValid) return;         // IME 组合中，放行
  ref.read(generationTriggerProvider).fire(nodeId);
}
```

同规则适用于：画布搜索栏、项目/画布名编辑、泳道标签编辑。

### 9.7 结果节点面板（只读模式）

点击结果节点（node_role = result）弹出只读面板：

- **顶部**：生成来源信息——"由 {源节点名称} 生成"，可点击跳转到源节点
- **中部**：参数快照只读展示——模型、比例、分辨率、prompt（灰色文字，不可编辑）
- **底部操作栏**：
  - [派生新节点] — 基于此结果创建新配置节点（语义详见下）
  - [下载] — 下载原始文件
  - [查看原图/原视频] — 打开灯箱
- **批量结果节点**：额外显示 slot 网格，点击 slot 切换查看，每个 slot 有独立的 [提升为独立节点] 按钮
- 面板宽度、位置、动画与配置节点面板一致（§9.1）

**派生新节点语义：**

| 字段 | 行为 |
|------|------|
| node_role | `config`（新节点可编辑） |
| source_node_id | 指向**原始 config 节点**（不是当前 result 节点），使派生节点与原配置节点是兄弟关系 |
| 复制字段 | prompt / model / aspect_ratio / resolution / camera_movement / negative_prompt |
| 不复制 | seed（用户可重新配置）、连线关系、generated url 等 |
| 连线建立 | 不自动建立，用户手动连 |
| 位置 | 源 result 节点右侧 60px，Y 坐标相同 |

## 10. Provider 接入系统

### 10.1 Provider 能力声明

每个 Provider 通过 `ProviderCapabilities` 声明支持的能力：

```dart
@freezed
class ProviderCapabilities with _$ProviderCapabilities {
  const factory ProviderCapabilities({
    required String providerId,                    // 唯一标识
    required ProviderRegion region,                // cn / global
    required List<GenerationMode> modes,           // text_to_image / image_to_image / text_to_video / image_to_video
    required List<AspectRatio> supportedRatios,    // 枚举完整列表（见下）
    required List<Resolution> supportedResolutions,// 720p / 1080p / 2K / 4K
    required List<int> supportedDurations,         // 视频时长（秒），图片 provider 为 []
    required List<CameraMovement> supportedCameras,// 运镜列表，空列表表示不支持
    required int  maxBatchSize,                    // 批量上限（视频固定 1）
    required int  maxRefImages,                    // 参考图上限（不含 first/last frame）
    required bool refImagesIncludeKeyframes,       // first/last frame 是否计入 maxRefImages
    required bool supportsFirstFrame,
    required bool supportsLastFrame,
    required bool supportsNegativePrompt,
    required bool supportsSeed,
    required bool supportsSound,
    required bool supportsBatch,
    required bool supportsCancellation,
    required CostModel costModel,                  // 计费口径，见 §10.1.1
    required int  maxConcurrentJobs,               // per-provider 并发上限（见 §10.7）
    Duration?     pollInterval,                    // null = 用全局默认 3s
    Duration?     pollTimeout,                     // null = 用全局默认 30min
  }) = _ProviderCapabilities;
}

// 标准枚举值
enum AspectRatio { r1x1, r16x9, r9x16, r4x3, r3x4, r21x9 }
enum Resolution  { p720, p1080, k2, k4 }
enum CameraMovement { static_, pushIn, pullOut, panLeft, panRight, tiltUp, tiltDown, orbit, handheld }
```

内联面板根据这些声明动态显示/隐藏参数。`supportedRatios` 为空或不包含当前值时，自动 fallback 到第一个支持值。

### 10.1.1 成本预估（统一口径）

**底层逻辑：** 不同 provider 计费单位差异大（字符数 / 生成次数 / 分辨率×时长），内联面板统一显示**"预估 USD 成本"**，而非 Token 数。

```dart
  const factory CostModel.perCharInput({
    required double usdPerKChar,                      // Gemini ≈ $0.000075/KChar input

double estimateCost(GenerationTask task, ProviderCapabilities caps) { ... }
```

- 中国区 Provider 按 7.2 CNY/USD 展示 `≈¥X.XX`，可在设置 → 常规切换显示币种
- UI 文案明示"预估仅供参考，以 Provider 官方账单为准"
- 预估不准确不影响任何业务流，仅用户心智参考

### 10.3 统一生成流程

```
参数验证 → 风格注入（拼接 prompt）→ 参考图处理
→ 创建结果节点（status: generating）+ generation_source 连线
→ 提交 Provider API → 轮询 → 成功/失败
→ 成功：下载到本地 + 生成缩略图 + 更新节点
→ 失败：更新节点 error 字段 + Toast 通知
```

**统一的轮询与重试参数：**

```dart
// lib/core/constants/network.dart
const Duration kPollInitialInterval  = Duration(seconds: 3);    // 初始轮询间隔
const double   kPollBackoffMultiplier = 2.0;                    // 退避系数
const Duration kPollMaxInterval      = Duration(seconds: 30);   // 间隔上限
const double   kPollJitter           = 0.2;                     // ±20% 抖动
const Duration kPollTimeout          = Duration(minutes: 30);   // 总超时
const int      kMaxRetries           = 3;                       // 最大重试次数（网络错误）
```

**可重试错误类型：** 网络超时、5xx、`provider_busy`。
**不可重试错误类型：** `invalid_key`、`insufficient_balance`、`content_policy_violation`、`invalid_parameter`。
Provider 可通过 `pollInterval` / `pollTimeout` 覆盖全局默认值（M2）。

### 10.3.1 产物下载与重试

生成成功后的 CDN 临时 URL 由独立阶段处理，**与生成流程解耦**：

```
polling ─success─► downloading ──► local_ready (node.status = success)
                      │
                      ├─ HTTP 失败 ─► retry (指数退避 3s/9s/27s，3 次)
                      │
                      └─ 重试耗尽 ─► node.status = error
                                     jobs.error_code = 'download_failed'
                                     jobs.status = 'error'
                                     保留 remote_url 于 jobs.parameters.remote_url
                                     面板提供"重新下载"按钮
```

**jobs 表字段扩展（非破坏性，仅用途说明）：**
- `parameters.remote_url` — 保留最后一次的远端 URL，供手动重下
- `parameters.remote_url_expires_at` — URL 过期时间戳（若 Provider 返回），过期后"重新下载"改为"从头重新生成"

**应用重启的下载续传：**
- 启动时扫描 `jobs WHERE status='error' AND error_code='download_failed' AND remote_url_expires_at > now()`，在任务中心显示"可恢复下载 N 项"banner，用户显式点击才重试（不自动消耗流量）。

**断点续传：** v0.1.0 不做 Range 断点续传，失败即整文件重下。

| 错误类型 | 提示 |
|---------|------|
| Key 未配置 | 跳转设置页 |
| Key 无效 | 跳转设置页 |
| 余额不足 | 提示 Provider 名称 |

### 10.5 代理配置

设置 → 网络：使用系统代理 / 手动配置 / 不使用。支持 Provider 级别覆盖（不同 Provider 用不同代理）。

**代理数据模型：** protocol (http/https/socks5)、host、port、username（可选）。密码存 SecureStorage，不进数据库。

代理配置（protocol/host/port/username）存 `~/InkFrame/config/settings.json` 的 `proxy` 字段。密码存平台安全存储（macOS Keychain / Windows Credential Manager），key 格式：`inkframe.proxy.{provider_id}.password`（全局代理用 `inkframe.proxy.global.password`）。

### 10.6 错误码统一枚举（InkError）

所有 Provider 实现、Job 持久化、Toast 文案、验收日志**必须**使用此枚举，不得自造字符串。

| code | 类别 | 可重试 | 默认文案 key | 触发场景 |
|------|------|-------|------------|---------|
| `invalid_key` | 鉴权 | 否 | errorInvalidKey | 401 / Key 被撤销 |
| `insufficient_balance` | 账号 | 否 | errorInsufficientBalance | 402 / 余额不足 |
| `content_policy` | 内容 | 否 | errorContentPolicy | 审核拒绝 |
| `invalid_parameter` | 请求 | 否 | errorInvalidParameter | 参数不合法（比例/分辨率/时长） |
| `network_timeout` | 网络 | 是 | errorNetworkTimeout | 连接/读写超时 |
| `network_offline` | 网络 | 是 | errorNetworkOffline | 本机无网络 |
| `provider_5xx` | 服务端 | 是 | errorProviderServer | Provider 5xx |
| `provider_busy` | 服务端 | 是 | errorProviderBusy | 429 / "请稍后" |
| `poll_timeout` | 轮询 | 否 | errorPollTimeout | 超 30 分钟未出结果 |
| `download_failed` | 产物 | 是 | errorDownloadFailed | 生成成功但文件下载失败 |
| `local_io_error` | 本地 | 否 | errorLocalIO | 磁盘满 / 权限拒绝 |
| `cancelled_by_user` | 用户 | — | errorCancelled | 用户主动取消 |
| `cancelled_on_exit` | 系统 | — | errorCancelledOnExit | app 退出时强制取消 |
| `unknown` | 兜底 | 否 | errorUnknown | 未分类异常（记日志） |

**字段对应：**
- `jobs.error_code` ∈ 上表 code
- `batch_results.error_code` ∈ 上表 code
- `KeyValidationResult.invalid(reason)` 的 reason 固定为 `invalid_key / insufficient_balance / content_policy / network_timeout / network_offline`
- Toast 使用 `errorMessage` 字段（i18n 后的完整描述），不直接显示 code

**可重试白名单（覆盖 §10.3）：** `network_timeout / network_offline / provider_5xx / provider_busy / download_failed`，其余一律不重试。

### 10.7 JobQueueService 并发规则

**拓扑：** 单例 `keepAlive`，app-scoped，横跨所有画布与项目。

**调度维度：**
- **全局并发上限** = 性能档位 `maxConcurrentJobs`（省电 1 / 均衡 2 / 性能 3 / 极致 4）
- **Per-provider 并发上限** = `ProviderCapabilities.maxConcurrentJobs`（默认 2，Gemini=1，Kling=2，海螺=2）
- 实际可调度数 = `min(全局剩余槽位, per-provider 剩余槽位)`

**状态流转（`jobs.status`）：**

```
pending (入队未提交) ──► submitted ──► polling ──► success / error / timeout
   │                                                      │
   └── cancelled_by_user（用户取消排队中任务）           │
                                                          │
   任何阶段 ──► cancelled_on_exit （app 退出 graceful）   │
```

**出队策略：** FIFO，相同 provider 的任务按 `created_at` 升序；跨 provider 抢占全局槽位也按 FIFO。

**UI 呈现：**
- 右下角"任务中心"悬浮入口（常驻），展示：进行中 N / 排队 M / 失败 K
- 点击展开抽屉，可取消排队中任务（点 result 节点面板取消 = 点抽屉取消，同一动作）
- 排队中 result 节点的 `status` 仍为 `generating`，面板显示"排队中 #3"副标题

**jobs.status='pending' 定义补丁：** §21 表未明示的 "pending" 语义，此处确认 = "已创建 result 节点，未提交 provider，等待槽位"。

### 12.4 自动保存

**脏标记增量保存：** 每次状态变更标记脏实体，防抖 5 秒后只写脏集合（去重），单事务 upsert。关闭画布/应用时立即保存。崩溃后下次启动从最近自动保存恢复。

**三种触发路径：**

```dart
const Duration kAutoSaveDebounce    = Duration(seconds: 5);   // 防抖等待
const Duration kAutoSaveMaxInterval = Duration(seconds: 30);  // 强制刷新上限
const int      kDirtySetMaxSize     = 1000;                   // 脏集合上限
```

1. **防抖触发**：最后一次操作后 5s 触发
2. **强制触发**：距上次保存超过 30s，立即保存（防用户连续输入永不触发）
3. **上限触发**：脏集合 ≥ 1000 个实体，立即保存（防内存膨胀）

**失焦/切换场景：**
- 切换画布、切换窗口失焦、关闭画布、应用退出 → 立即保存（忽略防抖）
- 清空防抖计时器，防止重复触发

**脏标记粒度定义：** 以"用户意图操作完成"为标记时机，非每帧/每字符：

| 操作 | 标记时机 | 脏实体 |
|------|---------|--------|
| 拖拽节点 | 鼠标松手时（非拖拽过程中每帧） | 被移动的节点 |
| 编辑 prompt | 输入停止 500ms 后 | 该节点 |
| 切换模型/参数 | 立即 | 该节点 |
| 创建/删除连线 | 立即 | 该连线 + 两端节点 |
| 创建/删除节点 | 立即 | 该节点 |
| 编辑泳道 | 输入停止 500ms 后 | 该泳道 |
| 批量移动 N 个节点 | 鼠标松手时 | N 个节点（N 条脏记录） |

**保存状态四态：** 已保存 / 保存中 / 待保存（有脏数据等待防抖）/ **保存失败**。

**失败处理：** 静默重试 3 次（5s / 15s / 30s 退避）。全部失败后状态栏显示持续红色"保存失败 — 点击重试"（不是 toast）。用户可继续操作，脏数据持续累积。磁盘满给具体提示，数据库锁继续重试。

### 12.6 相对路径契约与目录搬迁

**路径契约：**
- `type_config.image_url / video_url / thumbnail_url` 存储形如 `images/{node-id}.png` 的**画布目录相对路径**，根为 `~/InkFrame/projects/{project-id}/canvases/{canvas-id}/`。
- 读取时由 `FileResolverService` 拼回绝对路径，**禁止**任何层直接持有绝对路径。
- 项目/画布**改名不触发物理目录改名**（目录以 UUID 命名），用户可见名来自 DB `name` 字段，解耦展示与存储。

**整机搬迁：**
- 直接拷贝整个 `~/InkFrame/` 到新机器（含 `database/` PGDATA 与 `config/pg.port`），二进制 PG 版本一致即可启动。
- PG 版本不一致时，新机器启动检测 `schema_version + pg_ctl --version` 失配 → 弹"请先在旧机器执行 `pg_dumpall`"提示，不自动升级。

**设置 → 存储 → 切换数据目录：**

```
1. 弹确认框（说明将暂停 30s）
2. ref.read(jobQueueServiceProvider).pauseAll()            // 暂停新任务
3. 等待进行中 job 到达终态或 cancelled（超时 10s）
4. pg_ctl stop -m fast
5. 原子移动 ~/InkFrame → {新路径}（同盘 rename / 跨盘 copy+verify+rm）
6. 更新 ~/Library/Preferences/inkframe.plist (macOS) /
   HKCU\Software\InkFrame (Windows) 的 dataDir 键
7. pg_ctl start，校验 schema_version，恢复 job 队列
8. 失败任一步 → 回滚配置键 + 保留原目录 + 弹错误 + 导出诊断包
```

跨盘迁移 `verify` = 对每个视频/图片做 SHA-256 比对，抽样率 5%。

### 12.7 跨画布/跨项目复制节点

**P0：** 仅同画布内复制粘贴。

## 15. 缓存系统

### 15.1 缩略图系统

**生成时机：** 图片生成成功、视频生成成功（提取首帧）、拖入本地文件、九宫格裁切。

**四个档位：** micro (64px)、small (128px)、medium (256px)、large (512px)，JPEG 格式。

**按性能档位选择：** 省电→small，均衡→medium，性能→large，极致→原图。

**生成策略：** 每张源图仅生成**当前性能档位对应的一档**缩略图，不预生成全部四档。用户切换性能档位后按需 lazy 生成缺失的档位，不回溯补全历史档位。

### 15.2 内存缓存（LRU）

| 参数 | 省电 | 均衡 | 性能 | 极致 |
|------|------|------|------|------|
| 最大缓存数 | 30 | 80 | 150 | 300 |
| 预估内存 | ~50MB | ~150MB | ~300MB | ~600MB |

LRU 淘汰，优先淘汰离屏节点。加载优先级：视口内 > 1屏外 > 2屏外。

### 15.3 离屏节点渲染

视口内正常渲染，视口外按距离和性能档位逐级降级为缩略图 → 占位框（颜色块+标题）→ 不渲染。

缩放 < 30% 时所有节点降级为占位框。

### 15.4 缓存清理

源文件永久删除时清理对应缩略图。磁盘超限时淘汰最旧的。启动时扫描孤立缩略图。

设置 → 存储可查看和清理缓存，配置缩略图缓存上限。

### 16.1 操作栈

## 18. 多选批量操作

框选或 Mod+点击多选后，画布底部浮出批量操作栏：

```
已选 N 个节点  │ [批量删除] [移入泳道 ▼] [改模型 ▼] [导出] [取消选择]
```

多选状态下内联面板隐藏。

**批量移入泳道的坐标行为：**
- `lane_id` 更新为目标泳道 id
- `position_x/y` 自动平移：保持节点在原泳道内的相对偏移，映射到目标泳道坐标系
- 多节点整体平移，保持节点之间的相对位置不变，不触发重排
- 若目标泳道尺寸不够（节点超出），按原偏移放置，允许视觉溢出（后续拖动再调整）

**批量改模型兼容性规则：**
- 切换后，不兼容的参数自动降级为新模型的默认值（如分辨率、时长）
- 不兼容的 data 连线保留但标记警告图标，内联面板提示"当前模型不支持参考图输入"
- Toast 提示受影响的节点数量："已切换 N 个节点的模型，其中 M 个节点的参数已自动调整"

### Jobs 清理策略（Retention）

应用启动时异步执行，不阻塞主流程：

```sql
-- 规则 1：超过 30 天的终态 job 物理删除，但保留"孤儿 result 依赖"的 job
DELETE FROM jobs j
WHERE j.status IN ('success','error','cancelled','timeout')
  AND j.completed_at < now() - INTERVAL '30 days'
  AND NOT EXISTS (
    SELECT 1 FROM nodes n
    WHERE n.id = j.result_node_id
      AND n.deleted_at IS NULL
      AND n.source_node_id IS NULL           -- §4.5.1 孤儿 result，参数快照必须保留
  );

-- 规则 2：单个 canvas 的 job 总数超过 500 条时，保留最近 500 条（同样排除孤儿依赖）
WITH ranked AS (
  SELECT id, ROW_NUMBER() OVER (
    PARTITION BY canvas_id ORDER BY created_at DESC) AS rn,
    result_node_id
  FROM jobs
)
DELETE FROM jobs WHERE id IN (
  SELECT r.id FROM ranked r
  WHERE r.rn > 500
    AND NOT EXISTS (
      SELECT 1 FROM nodes n
      WHERE n.id = r.result_node_id
        AND n.deleted_at IS NULL
        AND n.source_node_id IS NULL
    )
);
```

### BatchResult 生命周期

**提升为独立节点：**

```
batch_results[slot_index=2, status=success]
  → 用户点击"提升为独立节点"
  → 创建新 result 节点：source_node_id = 原配置节点（与 batch 父节点为兄弟关系）
  → batch_results.promoted = true, promoted_node_id = 新节点 ID
  → 新节点独立存在，不再依赖 batch_results 行
```

**删除级联规则：**

| 操作 | batch_results 行为 | 已提升节点行为 |
|------|-------------------|---------------|
| 删除 batch 父节点（结果节点） | 级联删除所有 batch_results（ON DELETE CASCADE） | 已提升节点**保留**（独立存在，source_node_id 指向配置节点） |
| 删除原配置节点 | 不影响（batch_results 关联的是结果节点） | 已提升节点 source_node_id 置 NULL（ON DELETE SET NULL） |
| 清空回收站永久删除 | 同上，真正删除行和文件 | 同上 |

```sql

ALTER TABLE canvases    ADD CONSTRAINT chk_canvases_name    CHECK (char_length(name) <= 200);

ALTER TABLE style_lanes ADD CONSTRAINT chk_lane_label_len   CHECK (char_length(label) <= 100);
ALTER TABLE style_lanes ADD CONSTRAINT chk_lane_prompt_len  CHECK (char_length(style_prompt) <= 4096);
ALTER TABLE nodes       ADD CONSTRAINT chk_node_label_len   CHECK (char_length(label) <= 200);
```

### 22.1 嵌入式 PostgreSQL 运维规格

**二进制打包**（不放 Flutter `assets/` — 无可执行权限）：

```
macOS: macos/Runner/Resources/pg/bin/ + pg/lib/
  ├── macos-arm64/   (Apple Silicon)
  └── macos-x64/     (Intel Mac)

Windows: windows/runner/resources/pg/bin/ + pg/lib/
  └── windows-x64/
```

构建时按平台复制对应 PG 二进制到 resources。CI 从对象存储（S3/OSS）拉取二进制，**不进代码仓库**。每个平台构建只包含本平台二进制。

**版本锁定：** 固定 PostgreSQL 17.x（具体小版本在 `scripts/pg-version.txt` 中声明）。PG 大版本升级会破坏 data 目录兼容性，任何大版本变更必须附带 `pg_upgrade` 迁移脚本。CI 构建时校验拉取的二进制版本与声明一致。

**体积影响：** 应用包增加约 80-120MB。

**启动流程：**

```
首次启动：
  initdb → 初始化数据目录 ~/InkFrame/database/（3-5 秒）
  pg_ctl start → 监听 localhost:<随机端口>
  端口写入 ~/InkFrame/config/pg.port
  应用读取端口，建立连接池

非首次启动：
  pg_ctl start → 监听 localhost:<随机端口>（1-3 秒）
  端口写入 ~/InkFrame/config/pg.port

退出流程：
  ref.onDispose 触发
  等待当前事务完成（最多 5 秒）
  pg_ctl stop -m fast
```

**PG 崩溃恢复：**

```
应用启动 → 检查 ~/InkFrame/database/ 下的 postmaster.pid
  ├── 无 pid 文件 → 正常启动（pg_ctl start）
  ├── pid 文件存在，进程存活 → 复用，读端口连接
  └── pid 文件存在，进程已死 → 删除 pid 文件，pg_ctl start
```
| 平台 | macOS + Windows |

### 22.0 Schema 版本管理

数据库内置 `schema_version` 表（单行），记录当前 schema 版本号（整数递增）。

```sql
CREATE TABLE schema_version (
  id         INTEGER PRIMARY KEY DEFAULT 1
             CHECK (id = 1),           -- 物理层保证只能有一行
  version    INTEGER NOT NULL,
  applied_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- 初始化：UPSERT 写入首版版本号
INSERT INTO schema_version (id, version) VALUES (1, 1)
ON CONFLICT (id) DO UPDATE
  SET version = EXCLUDED.version,
      applied_at = now();
```

应用启动时检查 schema_version：
- 版本匹配 → 正常启动
- 版本低于应用期望 → 按序执行迁移脚本（`lib/storage/migrations/` 目录，文件名 `002_xxx.sql`、`003_xxx.sql`）
- 版本高于应用期望 → 提示用户升级应用版本

v0.1.0 为首版，schema version = 1，所有表直接 CREATE。后续版本通过迁移脚本增量变更。

## 27. 崩溃恢复

### 27.1 防护机制

| 机制 | 说明 |
|------|------|
| 自动保存 | 每 5 秒（可配置）保存到 PostgreSQL |
| 崩溃标记 | 启动时写入 `~/InkFrame/.running`（含 PID），正常退出时删除 |
| 日志文件 | `~/InkFrame/logs/inkframe.log`，保留最近 7 天 |
| 单实例锁 | 通过 `.running` PID 识别已有实例，详见 §27.4 |

### 27.2 崩溃检测与恢复

启动时检查 `.running` 文件 → 存在则上次崩溃 → 弹出恢复对话框：

```
⚠ InkFrame 上次未正常退出
上次打开的画布: "第1集"
上次保存时间: 12:35:20

[恢复上次状态]    [从项目列表开始]
```

恢复：直接打开上次画布，恢复视口。数据不丢失（自动保存的都在）。

### 27.3 日志

```
~/InkFrame/logs/
├── inkframe.log          ← 当前
├── inkframe.log.1        ← 昨天
└── ...                   ← 最多 7 天
```

记录：启动/关闭、生成任务、未捕获异常、Provider API 错误（不含 Key）。

设置 → 关于：`📋 日志目录 [打开目录]`

### 27.4 多窗口/多实例策略

**P0 阶段：单实例强制。**

```
应用启动 →
  检查 ~/InkFrame/.running
    ├── 不存在 → 写入 .running（PID+时间戳）→ 正常启动
    └── 存在 →
          ├── PID 进程存活 → 激活该进程窗口（macOS NSWorkspace / Windows SetForegroundWindow），当前进程退出
          └── PID 进程已死（崩溃残留）→ 删除 .running，走崩溃恢复流程（§27.2）
```

多窗口支持列入 P2 路线。

## 1. Product Vision

### What Is InkFrame

Open-source, local-first AI visual creation workstation for short drama and film production. Users bring their own API keys (BYOK), work entirely on desktop, and own all their data.

### Problem Statement

- Existing AI video creation tools are all web-based SaaS platforms that charge significant markup on API calls
- Web rendering is slow, laggy, and dependent on servers; data isn't in the user's hands
- Ordinary creators can't afford the cost; professionals find it expensive and restrictive
- AI-generated content (AIGC) feels inaccessible to regular people

### Core Proposition

- **Local-first** — Data stored in local embedded PostgreSQL; no server required; offline-capable (except AI generation API calls)
- **BYOK (Bring Your Own Key)** — Users provide their own official or third-party API keys; zero markup
- **Open-source & free** — MIT license, community-driven
- **Native experience** — Flutter Desktop, native rendering on macOS + Windows, no lag

### Target Users

- Independent creators (short dramas, short videos, social media content)
- Small studios (2-5 people, unable to afford SaaS fees)
- AIGC enthusiasts (want to try AI filmmaking but are deterred by existing tool barriers)

### What InkFrame Is Not

- Not an online collaboration platform (v0.1.0 is purely local single-user)
- Not a video editing software (no timeline/NLE)
- Not a model training tool

## 2. Core User Scenarios

### Scenario 1: Image-to-Video Creation (P0 — Core Loop)

```
Create canvas → Add image node → Write prompt + select model + set params
→ Generate → Wait for result → Drag out video node
→ Connect (image → video) → Image auto-used as reference
→ Configure video params (duration/camera movement) → Generate video → Preview/Download
```

User has a visual idea, generates an image first, iterates until satisfied, then generates a 5-second video from that image. Repeats for multiple shots.

### Scenario 2: Reference-Driven Batch Production (P0)

```
Drag local reference image onto canvas → Draw connection to new image node
→ Connection type = "reference" → Write prompt describing variation
→ Generate style-consistent new image → Connect to video node → Generate video
```

User has character design art, wants to generate different scenes/actions for the same character while maintaining style consistency.

### Scenario 3: Script-Driven Storyboard Production (P1)

```
Import/paste script text → AI parses script → Auto-split into Scene + Shot structure
→ Each Shot gets: narrative description + cinematography + 6-dimension analysis
→ System generates multi-grid prompt per Shot
→ Generate 9-grid/4-grid image (multiple keyframes in one image for consistency)
→ Auto-crop into individual keyframe images
→ User reviews on canvas: keep good ones, edit/regenerate bad ones
→ Drag approved keyframes into storyboard Shot node
→ Shot node: keyframes arranged horizontally + narrative prompt
→ Click "Generate Video" → multi-reference-image video generation (Kling/Seedance)
→ Video result displayed in Shot node → Preview on canvas
```

#### Storyboard Shot Node Design

```
+----------------------------------------------------------------------+
| Shot #1  "Character pushes door open"  Mid-shot / Push-in            |
| Narrative: Character slowly pushes heavy wooden door, dim interior   |
|                                                                      |
|  Keyframes (horizontal, add/remove):                     +--------+  |
|  +------+ +------+ +------+ +------+                    | Generate|  |
|  |Frame1| |Frame2| |Frame3| |Frame4|  ...               |  Video  |  |
|  |      | |      | |      | |      |                    |         |  |
|  +--+---+ +--+---+ +--+---+ +--+---+                    +--------+  |
|     |x       |x       |x       |x                                   |
|                                                                      |
|  Prompt: A man pushes open a heavy wooden door, dim interior...      |
|  Model: Kling 3.0 Multi-ref | Duration: 5s | Camera: Push-in        |
|                                                                      |
|  +--------------------+                                              |
|  | > Generated video   |                                             |
|  +--------------------+                                              |
+----------------------------------------------------------------------+
```

**Canvas-Storyboard Relationship:**
- Canvas = creative workspace (free image generation, 9-grid, editing, iteration)
- Storyboard = production pipeline (organize approved assets into shots, generate videos)
- Canvas image nodes can be referenced by multiple Shot nodes
- Keyframes in a Shot are references to canvas images, not copies
- Shots connected by narrative-order edges, visible on canvas
- Generated videos visible directly in Shot nodes on canvas

#### Multi-Grid Image Generation (Consistency Mechanism)

One Shot's content generates a single multi-grid image (4-grid or 9-grid), ensuring all keyframes share consistent style/character/lighting because they're produced in one generation pass.

```
9-grid generation → auto-crop → 9 individual keyframe images
→ User keeps useful ones, discards/edits the rest
→ Approved keyframes added to Shot node as video reference images
```

Grid count scales with model capability: 4 → 9 → 16+

### Scenario 4: Asset Reuse and Management (P2)

```
Generate satisfactory character image → Right-click "Save as Asset"
→ Tag: name, type, trigger words
→ Later: new node → @mention that character asset → Auto-inject reference + trigger words
→ Maintain character consistency across entire production
```

## 3. Style Zone System

### Problem

Without style management, consecutive shots may shift between photorealistic and anime styles, breaking visual coherence.

### Solution: Style Lanes (Swimlane Design)

The canvas is divided into **style lanes** — horizontal or vertical bands with distinct background tints and gradient boundary lines between them.

```
+----------------------------------------------------------------------+
| Project Base Style: Live-action film, 4K, cinematic          [Edit]  |
+----------------------------------------------------------------------+
|                                                                      |
|  Style: Indoor Restaurant / Warm Light / Dusk                        |
|  (warm orange tint background)                                       |
|                                                                      |
|    [Image] [Image] [Shot#1] --> [Shot#2]                             |
|                                                                      |
|====== Gradient Boundary Line (warm orange fading to cool blue) ======|
|                                                                      |
|  Style: Street / Rainy Night / Neon                                  |
|  (cool blue tint background)                                         |
|                                                                      |
|    [Image] [Shot#3] --> [Shot#4] --> [Shot#5]                        |
|                                                                      |
|====== Gradient Boundary Line ========================================|
|                                                                      |
|  Style: Convenience Store / Fluorescent Light / Late Night           |
|  (cyan-white tint background)                                        |
|                                                                      |
|    [Shot#6] --> [Shot#7]                                             |
|                                                                      |
+----------------------------------------------------------------------+
```

### Style Zones Can Describe

| Type | Examples |
|------|----------|
| Location | Restaurant, office, street, rooftop |
| Time | Dawn, dusk, midnight |
| Weather | Rain, snow, fog, clear |
| Lighting | Backlight, side light, neon, candlelight |
| Mood | Tense, warm, eerie, romantic |
| Art style | Photorealistic, Chinese animation, ink wash, cyberpunk |

### Style Injection Logic

When generating any image/video, prompt is automatically assembled:

```
Final prompt = Project base prefix
             + Outermost zone style
             + ... (nested zones)
             + Innermost zone style
             + Node's own prompt
             + Project base suffix
```

### Operations

| Operation | Method |
|-----------|--------|
| Add zone | "+" button on boundary line, or toolbar button |
| Delete zone | Right-click zone title → Delete (nodes merge into adjacent zone) |
| Resize | Drag boundary line |
| Move nodes | Drag node across boundary → auto-inherit new zone's style |
| Reorder zones | Drag zone title to reorder |
| Layout toggle | Toolbar button: horizontal / vertical lanes |
| Edit style | Double-click zone title bar |
| Auto-tint | Zone background color auto-matched from style keywords; manual override available |
| Skip style | Per-node toggle: "Ignore zone style" (for experiments) |

## 4. Connection Types

| Connection Type | Meaning | Visual Style |
|----------------|---------|--------------|
| **Reference** | Image node → Shot keyframe or image node (style/content reference) | Dashed, blue |
| **Narrative order** | Shot#1 → Shot#2 → Shot#3 (story sequence) | Solid, white/gold |
| **Style reference** | Image → Image (style transfer) | Dashed, purple |
| **Generation source** | 9-grid → Cropped child images | Thin, gray |

## 5. AI Interaction Model

### Approach: Inline Panel + Command Bar (Hybrid)

**Single-node operations** → Click node → Inline panel (fast, efficient):
- Prompt textarea
- Model selector (filtered by capability: image/video)
- Aspect ratio, duration, camera movement
- Reference image drop zone
- Advanced: negative prompt, seed
- [Generate] button

**Batch/smart operations** → Cmd+K command bar:
- v0.1.0: Slash commands only (`/generate`, `/batch-generate`)
- P1+: AI conversation capability (natural language → batch operations on selected nodes)

| Module | Features |
|--------|----------|
| **Asset Library** | Character/scene/prop assets; save, tag trigger words, @mention injection; cross-canvas reuse |
| **AI Conversation** | Command bar upgrade to multi-turn dialogue; batch intelligent operations |

### Explicitly Excluded

| Item | Reason |
|------|--------|

## 7. Export System

### Two Export Entry Points

| Entry | Selection | Sort Logic |
|-------|-----------|------------|
| **Canvas Export** | Select/all video nodes on canvas | By spatial position (left→right, top→bottom) |
| **Storyboard Export** | Select/all Shot nodes | By narrative connection order |

Both support identical output formats.

### Output Formats

| Format | Target Software | Priority |
|--------|----------------|----------|
| **Numbered files + ZIP** | Universal | P1 |
| **EDL** (.edl) | All NLE software | P1 |
| **Jianying Draft** (.json) | Jianying Pro (CapCut CN) | P1.5 |
| **FCPXML** (.fcpxml) | Final Cut Pro | P2 |
| **AAF** (.aaf) | Premiere Pro, After Effects, DaVinci Resolve | P2 |
| **DaVinci Resolve XML** (.xml) | DaVinci Resolve | P2 |

### Output Structure

```
InkFrame_Export_20260411/
├── 001_Shot1_CharacterPushesDoor.mp4
├── 002_Shot2_Dialogue.mp4
├── 003_Shot3_VillainTurns.mp4
├── project.edl                    ← Timeline project file
├── metadata.json                  ← Index + duration + prompt per clip
└── storyboard.txt                 ← Storyboard script text
```

### NLE Import Behavior

- Video clips auto-arranged on V1 track in sequence order
- Audio tracks (from models that generate audio, e.g., Veo 3.1) auto-separated to A1 track
- Clip names preserve Shot titles for easy identification
- Head-to-tail arrangement, no gaps
- User only needs to: add transitions, color grade, add music, fine-tune

### Audio Handling

- Models that return video with audio track (e.g., Veo 3.1): audio preserved as-is
- Export splits video (V1) and audio (A1) into separate tracks in project files
- Models without audio: video-only on V1, A1 empty

### Single Node Download

Right-click any image/video node → Download → Original file saved locally.

## 8. Non-Functional Requirements

### Performance

| Metric | Requirement |
|--------|-------------|
| Canvas node count | 200+ nodes, smooth 60fps interaction |
| Canvas zoom/pan | No lag, GPU-accelerated rendering |
| Image loading | Thumbnail lazy-loading, full-size on demand |
| Video preview | Inline playback within node, no popup window |
| Cold start time | < 3 seconds |
| Memory usage | 100-node canvas < 1GB RAM |

### Storage

| Item | Approach |
|------|----------|
| Project/canvas/node data | Local embedded PostgreSQL |
| Generated images/videos | Local filesystem, organized by project/canvas directory |
| API Keys | macOS Keychain / Windows Credential Manager |
| User settings | Local JSON config file |
| Cloud dependency | None, except AI generation API calls |

### Platform

| Platform | Priority | Minimum OS |
|----------|----------|------------|
| macOS | P0 | macOS 12+ (Monterey) |
| Windows | P0 | Windows 10 21H2+ |
| Linux | Not planned | — |

### Network

| Scenario | Handling |
|----------|---------|
| Offline | Canvas editing, node management, project management fully available |
| Generation requests | Requires internet; calls Provider APIs |
| Reconnection | Generation tasks auto-retry with exponential backoff (max 3 retries) |
| Proxy support | System proxy + manual proxy address configuration |

### Security

| Item | Requirement |
|------|-------------|
| API Keys | Platform secure storage only; never written to database, logs, or config files |
| Data privacy | All data stored locally; no telemetry data uploaded |
| Open-source audit | MIT license, fully open codebase |

### Internationalization

| Language | Coverage |
|----------|----------|
| English | 100% (development language, source of truth) |
| Chinese | 100% (synchronized every commit) |

Token foundation

lib/theme/tokens.dart · typography.dart · motion.dart

Every value below is the real Dart symbol. Colours & type are reached through a BuildContext extension; spacing/radius/shadow/motion are static. Access pattern (live convention): final colors = context.inkColors; final typo = context.inkTypography; then InkSpacing.md, InkRadius.lg, InkShadow.card, InkMotion.fast. There is no InkColors.of() — colours arrive via the AppThemeExtension ThemeExtension.

Hard rule from the codebase

Wires & edge roles

EdgeType.data · EdgeRole

Edges connect an out anchor to an in anchor. Data edges carry a role (set on the target's input row): Reference · First frame · Last frame. Idle edges are subtle dashed; active edges (flowing into a selected or generating node) use the amber gradient with a glow halo and travelling flow dots.

14

Fidelity notes — design vs current code

read before implementing

Where this proposal diverges from today's build

  • Inspector placement. This design floats the Config panel over the canvas (top-right, InkShadow.elevated). The current code renders it as a fixed 320px panel. Pick one; the field set is identical either way.
  • Capability-aware fields. Image & video inspectors should render Aspect ratio / Seed / Negative prompt / Batch gated on the existing flags (supportedRatios, supportsSeed, supportsNegativePrompt, supportsBatch+maxBatchSize). Today only Resolution/Duration are wired.
  • Camera movements. Enum + l10n exist but supportedCameras is empty for all 9 providers. Either fill per provider or hide the control when the list is empty.
  • Inspector progress is a placeholder. InspectorSubmitRunning.progress is currently always null; authoritative progress is the render queue. Keep the inspector status terse (Submitting / Generating…) and let the queue own the % bar.
  • Node type ↔ strip colour mapping (§03) is a design decision to ratify; wire it as a single lookup so it stays token-driven.

Ready to implement

  • All colours/spacing/radii/type here map 1:1 to context.inkColors / InkSpacing / InkRadius / context.inkTypography — no new tokens required for Amber Noir.
  • All user-facing strings use existing ARB keys (quoted throughout) — no new i18n needed for the states shown, except any proposed controls.
